Les modules Ruby : include, prepend, extend

Le cours 4 a présenté les modules comme des « packs de compétences » que l'on donne à des classes. Ce complément va plus loin : où le module se place dans la recherche des méthodes selon qu'on l'inclut (include), qu'on le place devant la classe (prepend) ou qu'on l'ajoute à un seul objet (extend), et comment initialiser les variables d'instance qu'un module apporte.

Un module regroupe des méthodes réutilisables diapos 1–3

Un module ne crée pas d'objet par lui-même : il fournit des méthodes que des classes reprennent. Il faut donc savoir ce que devient une méthode du module dans la classe, et laquelle l'emporte quand les deux en définissent une du même nom.

Définition Module, mixin

Un module regroupe des méthodes et des constantes réutilisables. Il ne crée pas d'objet par lui-même : il est « mélangé » dans une classe. Inclus par include, il devient un mixin (mix-in) : ses méthodes deviennent des méthodes d'instance de la classe. C'est le mécanisme le plus courant.

Exemple Le module Tracable diapo 3

module Tracable
  def horodatage = "Créé le #{Time.now}"
end
# Il ne crée pas d'objet par lui-même : il est "mélangé" dans une classe.

class Commande
  include Tracable
end
# Les méthodes du module deviennent des méthodes d'instance.
# C'est le mécanisme le plus courant pour un mixin.

Commande.new.horodatage
# => "Créé le 2026-10-11 17:26:09 +0200"

# Ordre de recherche avec include
Commande.ancestors
# => [Commande, Tracable, Object, Kernel, BasicObject]

def horodatage = … est une définition sans fin (endless method, Ruby 3.0 et suivants) : une méthode d'une seule expression, sans end.

Attention horadatage ou horodatage À vérifier

La diapo appelle Commande.new.horadatage, avec un « a », alors que la méthode du module s'appelle horodatage. Tel quel, l'appel lève NoMethodError (« undefined method `horadatage' for an instance of Commande ») ; corrigé ici. La même faute revient diapo 9.

L'ordre de recherche des méthodes diapo 3

ancestors donne la liste dans laquelle Ruby cherche une méthode envoyée à un objet de la classe, dans l'ordre. Avec include, le module se place juste après la classe.

  • Le module Kernel est inclus par la classe Object (c'est lui qui fournit puts, print, rand…).
  • BasicObject est la classe parente de toutes les classes en Ruby ; en particulier, c'est la classe parente d'Object.

Propriété Priorité de la classe sur le module inclus

Si Commande et Tracable définissent la même méthode, c'est celle de Commande qui est utilisée : elle est trouvée la première.

Les variables d'instance d'un module diapo 4

Un module peut utiliser des variables d'instance (@cree_le). Mais un module n'a pas d'objets à lui : où ces variables vivent-elles, et qui leur donne leur valeur de départ ?

  • Il peut y avoir des variables d'instance dans un module.
  • Ces variables d'instance sont ajoutées à toute classe qui utilise le module : elles vivent dans chaque objet de la classe.
  • Se pose alors le problème de l'initialisation de ces variables d'instance à l'instanciation.

Méthode Quatre solutions possibles

  1. Une méthode d'initialisation définie dans le module et appelée explicitement dans l'initialize de la classe.
  2. Une méthode initialize dans le module, qui doit aussi être appelée explicitement dans l'initialize de la classe.
  3. L'initialisation paresseuse.
  4. Utiliser le module avec prepend, qui inverse l'ordre de recherche par rapport à include.

Solution 1 : une méthode d'initialisation explicite diapos 5–6

La façon la plus simple : le module offre une méthode qui crée ses variables, et la classe l'appelle elle-même dans son initialize.

Propriété Les variables appartiennent à l'objet

Les variables d'instance appartiennent à l'objet, pas au module. @cree_le sera stockée dans chaque objet qui utilise le module.

Exemple Initialisation explicite diapos 5–6

module Tracable
  def initialiser_horodatage
    @cree_le = Time.now
  end
  def horodatage = "Créé le #{@cree_le}"
end

# Initialisation explicite
class Document
  include Tracable

  def initialize(titre)
    @titre = titre
    initialiser_horodatage
  end
end

doc = Document.new("Rapport")
puts doc.horodatage
# => Créé le 2026-10-11 12:01:00 +0200

La classe hôte appelle une méthode d'initialisation du module : le module fournit le comportement, la classe décide quand l'initialiser. C'est simple, lisible et sans dépendance à super.

Solution 2 : un initialize dans le module diapos 7–8

On peut vouloir que le module s'initialise « tout seul », en lui donnant son propre initialize. Avec include, ce n'est pas automatique.

Exemple Le piège de initialize avec include diapo 7

module Tracable
  # pour initialiser les variables d'instance du module
  def initialize
    @cree_le = Time.now
    super
  end
  def horodatage = "Créé le #{@cree_le}"
end

class Commande
  include Tracable
  def initialize(client)
    @client = client
    # Oubli de super !
  end
end

Commande.new("Robert").horodatage
# => "Créé le "     (@cree_le vaut nil)

L'initialize de Commande est trouvé le premier (la classe passe avant le module) : celui du module n'est exécuté que si la classe l'appelle par super.

Attention Pourquoi c'est fragile diapo 7

  • Le initialize du module n'est pas appelé automatiquement : il nécessite un super dans la classe hôte.
  • Un oubli laisse des variables d'instance à nil.
  • Les arguments doivent être transmis correctement.
  • Avec plusieurs modules, la chaîne d'appels devient difficile à suivre.

Exemple Avec super(), et ses parenthèses diapo 8

class Commande
  include Tracable
  def initialize(client)
    @client = client
    super() # ATTENTION à ne pas oublier les parenthèses.
            # Sinon super invoque initialize avec le meme
            # nombre d'arguments reçus (1)
  end
end

# Ordre de recherche avec include
Commande.ancestors
# => [Commande, Tracable, Object, Kernel, BasicObject]

Complément super et super()

Écrit seul, super appelle la méthode de même nom plus haut dans ancestors en lui retransmettant tous les arguments reçus. Ici, super enverrait client à Tracable#initialize, qui n'en attend aucun : Ruby lève ArgumentError (« wrong number of arguments (given 1, expected 0) »), vérifié avec Ruby 3.3. super() appelle la même méthode sans argument. Le super du module, lui, peut rester sans parenthèses : il ne reçoit rien et transmet rien à Object#initialize.

Solution 3 : l'initialisation paresseuse diapo 9

Plutôt que de créer la variable à l'instanciation, on la crée la première fois qu'on en a besoin. La classe hôte n'a alors rien à faire.

Exemple @cree_le ||= Time.now diapo 9

module Tracable
  def cree_le
    @cree_le ||= Time.now
  end
  def horodatage
    "Créé le #{cree_le()}"
  end
end

class Commande
  include Tracable
  def initialize(client)
    @client = client
  end
end

c=Commande.new("Robert")
# => #<Commande:0x0000000124cc6c60 @client="Robert">
c.horodatage
# => "Créé le 2026-10-11 17:48:21 +0200"
c.inspect
# => #<Commande:0x0000000124cc6c60 @client="Robert", @cree_le=2026-10-11 17:48:21.551847 +0200>

La variable est créée lors du premier appel : avant horodatage, l'objet n'a que @client ; après, il a aussi @cree_le. Le support écrit encore c.horadatage, corrigé ici (voir la diapo 3).

Attention La date du premier accès

La date correspond alors au premier accès, pas forcément à la création de l'objet.

Complément Ce que fait ||=

@x ||= v se lit @x || (@x = v) : si @x vaut déjà quelque chose de vrai, on le garde ; s'il vaut nil (variable jamais affectée) ou false, on lui donne v. Pour un compteur, @n ||= 0 donne 0 à un objet qui n'a encore rien compté : c'est la solution du module Detente du TD 4. Toutes les méthodes du module doivent alors passer par l'accesseur (cree_le()), jamais par @cree_le directement.

Solution 4 : prepend diapos 10–11

Avec prepend, le module se place avant la classe dans l'ordre de recherche : ses méthodes sont trouvées les premières, et c'est lui qui appelle celles de la classe par super.

Exemple Un initialize de module exécuté avant celui de la classe diapo 10

module Tracable
  def initialize()
    @cree_le = Time.now
    super
  end
  def horodatage
    "Créé le #{@cree_le}"
  end
end

class Commande
  prepend Tracable

  def initialize(client)
    @client = client
  end
end

# Ordre de recherche avec prepend
Commande.ancestors
# => [Tracable, Commande, Object, Kernel, BasicObject]
# Rappel Ordre de recherche avec include
# => [Commande, Tracable, Object, Kernel, BasicObject]

Ici, l'initialize du module s'exécute avant celui de la classe. Le module peut donc intercepter, enrichir ou remplacer le comportement de la classe.

Attention Les arguments de initialize À vérifier

Tel qu'il est écrit, l'exemple ne permet pas de créer une commande : Commande.new("Robert") appelle d'abord Tracable#initialize, qui n'accepte aucun argument, et Ruby 3.3 lève ArgumentError (« wrong number of arguments (given 1, expected 0) »). Le module doit accepter les arguments de la classe et les lui retransmettre par super sans parenthèses :

module Tracable
  def initialize(...)     # ou : def initialize(*args)
    @cree_le = Time.now
    super                 # retransmet les arguments à Commande#initialize
  end
  def horodatage = "Créé le #{@cree_le}"
end

c = Commande.new("Robert")   # avec prepend Tracable
c.instance_variables
# => [:@cree_le, :@client]

(...) (Ruby 2.7 et suivants) accepte tous les arguments, nommés et bloc compris. C'est ce qu'annonce la diapo 14 : prepend garantit l'initialisation, à condition que le module ne fasse pas d'hypothèse sur les arguments de la classe.

prepend : cas d'usage diapo 11

Exemple Un journal devant une méthode diapo 11

module Journal
  def enregistrer(message)
    puts "[LOG] #{message}"
    super
  end
end

class Tache
  prepend Journal

  def enregistrer(message)
    puts "Enregistrement : #{message}"
  end
end

Tache.new.enregistrer("rapport")
# [LOG] rapport
# Enregistrement : rapport

Le module passe avant la méthode de la classe, fait son travail, puis lui laisse la main par super. C'est utile pour la journalisation, la validation, le cache ou les mesures de performance, sans toucher au code de la classe.

Une autre utilisation : extend diapo 12

include et prepend donnent les méthodes du module à toutes les instances d'une classe. extend les donne à un seul objet : une instance précise, ou la classe elle-même.

Exemple extend dans un objet diapo 12

module Exportable
  def exporter
    "Export de #{@titre}"
  end
end

class Document
  def initialize(type)
    @type=type
  end
end

# `extend` dans un Objet
doc = Document.new("Notes")
doc.extend(Exportable)
doc.exporter
# => "Export de Notes"

rap = Document.new("Rapport")
rap.exporter
# => undefined method 'exporter' for an instance of Document ....

Seul doc possède la méthode exporter : les autres documents, comme rap, ne l'ont pas.

Exemple extend dans une classe diapo 12

class Document
  extend Exportable
end

Document.exporter

Utilisé dans une classe, extend ajoute des méthodes de classe : Document.exporter, et non doc.exporter.

Attention @type ou @titre À vérifier

Le constructeur range son paramètre dans @type, mais exporter lit @titre, qui n'existe pas : avec Ruby 3.3, doc.exporter donne "Export de " et non "Export de Notes". Il faut écrire def initialize(titre) = @titre = titre. De même, Document.exporter donne "Export de " : dans une méthode de classe, @titre est une variable de l'objet Document (la classe), qui n'en a pas.

Complément Où va le module ?

doc.extend(Exportable) inclut le module dans la classe singleton (singleton class) de doc, une classe propre à cet objet, placée devant Document : doc.singleton_class.ancestors commence par [#<Class:#<Document…>>, Exportable, Document, …]. extend dans une classe fait la même chose avec la classe singleton de la classe, où vivent ses méthodes de classe (celles que l'on définit par def self.creer).

Quelle solution choisir ? diapos 12–14

Les trois mécanismes ajoutent les mêmes méthodes, mais pas au même endroit ni pour les mêmes objets.

Comparaison rapide diapo 12
MécanismeAjoute des méthodesPortéeCas typique
included'instancetoutes les instancescapacité commune
prependd'instancetoutes les instancesintercepter ou enrichir
extendsingleton ou de classeun objet, ou la classecomportement ponctuel

Méthode Quelle solution choisir ? diapo 13

  • include : ajouter des capacités ordinaires aux instances.
  • prepend : modifier ou observer le comportement existant.
  • extend : ajouter une capacité à un objet précis ou à une classe.
  • Méthode d'initialisation explicite : pour initialiser proprement les variables du module.

Astuce Bonnes pratiques diapo 14

  • Préférer une méthode comme init_xxx à un initialize dans un module inclus.
  • Utiliser prepend si le module doit garantir une initialisation.
  • Documenter toute obligation d'appeler super.
  • Éviter les modules trop dépendants de la structure interne des classes hôtes.

Complément Un module qui compte sur sa classe hôte

Un module peut aussi appeler une méthode qu'il ne définit pas, et que chaque classe hôte doit fournir : c'est le module Critere du TD 5, dont correspond? appelle estSatisfaitPar?. Ainsi font Comparable (qui compte sur <=>) et Enumerable (sur each). Cette dépendance se documente, comme l'obligation d'appeler super.

À retenir

À retenir diapo 15

  • Un module fournit du comportement, pas un état propre : il ne crée pas d'objet.
  • Les variables d'instance vivent dans l'objet, pas dans le module.
  • include place le module après la classe : la classe garde la priorité.
  • prepend place le module avant la classe : il intercepte ses méthodes et lui rend la main par super.
  • extend cible un objet (méthodes singleton) ou une classe (méthodes de classe).
  • Avec include, un initialize de module nécessite un super explicite dans la classe, et super() s'il ne prend pas d'arguments.
  • Pour initialiser les variables d'un module : une méthode d'initialisation appelée par la classe, ou une initialisation paresseuse (@x ||= valeur).

Auto-évaluation

Que renvoie Commande.ancestors si Commande fait include Tracable ? Et avec prepend ?

[Commande, Tracable, Object, Kernel, BasicObject] ; avec prepend, [Tracable, Commande, Object, Kernel, BasicObject].

Une classe et le module qu'elle inclut définissent tous deux to_s. Laquelle est appelée ?

Celle de la classe, trouvée la première. Avec prepend, ce serait celle du module.

Un module inclus a un initialize sans paramètre ; la classe a initialize(client) et appelle super. Que se passe-t-il ?

super sans parenthèses retransmet client : ArgumentError (1 argument donné, 0 attendu). Il faut super().

Quel est l'inconvénient de l'initialisation paresseuse d'un horodatage ?

La date enregistrée est celle du premier accès, pas forcément celle de la création de l'objet.

Après doc.extend(Exportable), un autre document peut-il appeler exporter ?

Non : seul doc a reçu la méthode (dans sa classe singleton) ; les autres lèvent NoMethodError.

Que fait extend Exportable écrit dans le corps d'une classe ?

Il ajoute les méthodes du module comme méthodes de classe : Document.exporter.
