Retour sur la récursivité

Une fonction récursive s'appelle elle-même, comme une définition par récurrence s'appuie sur le rang précédent. Ce chapitre, première partie du cours sur les arbres, montre comment s'exécutent les appels, quand préférer l'itération, comment dérécursiver une fonction, et les formes de récursivité : multiple, mutuelle, imbriquée.

Définition et déroulement diapos 11–35

La récursivité est inhérente à la programmation fonctionnelle ; en C, il s'agit de la mettre en œuvre et de savoir écrire des fonctions récursives.

Définition Fonction récursive

Une fonction récursive est une fonction qui fait appel à elle-même. C'est l'équivalent de la définition par récurrence en mathématiques.

Exemple La factorielle

\(1! = 1\) et \(n! = n \times (n-1)!\) pour \(n \gt 1\). La définition a deux cas : celui où le résultat est immédiat, et celui où il se calcule par récursivité.

/* fonction qui renvoie n! */
int fact(int n) {
       if (n == 1)
              return 1;
       return n * fact(n-1);
}
/* Appel : printf("%i", fact(3)); */

L'appel fact(3) se déroule ainsi : fact(3) a besoin de fact(2), qui a besoin de fact(1) ; fact(1) vaut 1, donc fact(2) = 2 × 1 = 2, donc fact(3) = 3 × 2 = 6.

fact(3) = 3*fact(2)
              ↓
           fact(2) = 2*fact(1)
                         ↓
                      fact(1) = 1

fact(3) → fact(2) → fact(1)
                       ↓
   6    ←    2    ←    1

Dans fact, les calculs s'effectuent au retour des appels récursifs : chaque multiplication attend le résultat de l'appel qu'elle a lancé.

Une variante avec un accumulateur

On peut passer le résultat partiel en paramètre :

/* fonction qui renvoie n! */
int fact2(int n, int result){
       if (n == 1)
              return result;
       return fact2(n-1, n*result);
}
/* Appel : printf("%i", fact2(3,1)); */

À vérifier La diapo 28 écrit l'appel factorielle(3,1) : la fonction s'appelle fact2.

fact2(3,1) = fact2(2,3) = fact2(1,6) = 6

fact2(3,1) → fact2(2,3) → fact2(1,6)
                              ↓
    6      ←     6      ←     6

Ici, les calculs s'effectuent au moment des appels : le résultat est complet quand on atteint le cas immédiat, et les retours ne font que le transmettre.

Attention Le cas immédiat doit être atteint Ajout

Avec fact(0), ou un n négatif, la condition n == 1 n'est jamais vraie : les appels s'enchaînent jusqu'à épuiser la pile (erreur de segmentation, stack overflow). Une fonction récursive doit vérifier que chaque appel rapproche du cas immédiat ; ici, tester n <= 1 suffit, et donne aussi \(0! = 1\).

Objets locaux et globaux diapos 36–46

Pour comprendre une fonction récursive, il faut savoir ce que partagent ses différents appels.

Propriété Un exemplaire par appel

À l'exécution, il est créé en mémoire autant d'exemplaires de la fonction qu'il y a d'appels récursifs. Chaque exemplaire a son propre exemplaire des variables locales et des paramètres.

Pendant fact(3), trois paramètres n coexistent : 3, 2 et 1, un par appel. De même, une variable locale int a de f_rec peut valoir 5 dans le premier appel, 8 dans le deuxième et 2 dans le troisième. Ces exemplaires sont les contextes empilés dans la pile d'exécution.

Les variables globales, en revanche, n'existent qu'en un exemplaire, partagé par tous les appels. Cas particulier des pointeurs : chaque appel reçoit sa copie du pointeur, mais toutes les copies pointent à la même adresse, donc sur le même objet.

Exemple Somme ou produit selon le marqueur

Lire une suite d'entiers positifs terminée par un marqueur, et calculer leur somme si le marqueur vaut −1, leur produit s'il vaut −2 : 5 8 2 -1 donne 5 + 8 + 2 = 15 ; 1 2 1 4 -2 donne 1 × 2 × 1 × 4 = 8. Écrire un programme récursif, sans pile ni tableau.

Remarques de l'enseignant
  • On ne peut pas calculer au fur et à mesure : l'opérateur n'est connu qu'à la fin. On mémorise donc chaque valeur lue dans une variable locale, un exemplaire par appel.
  • L'opérateur et le résultat sont uniques : on utilise une variable globale ou un paramètre pointeur.
Correction 
#include <stdio.h>

int marqueur; /* -1 ou -2 */

void calcul (int * result){
     int x;
     scanf("%i", &x);
     if (x == -1){
           marqueur = -1;
           *result = 0;
     }
     else if (x == -2){
           marqueur = -2;
           *result = 1;
     }
     else   /* x est un entier positif */
     {
           calcul(result);
           if (marqueur == -1)
                 *result = *result + x;
           else
                 *result = *result * x;
     }
}

int main()
{ int resultat; /* valeur du résultat */
  calcul (&resultat);
  printf("La valeur est : %i\n",resultat);
}
$ echo "5 8 2 -1" | ./marqueur
La valeur est : 15
$ echo "1 2 1 4 -2" | ./marqueur
La valeur est : 8

Chaque appel garde son x dans sa variable locale ; quand le marqueur est lu, le dernier appel initialise le résultat (0 pour une somme, 1 pour un produit, les éléments neutres), puis chaque appel ajoute ou multiplie son x en remontant. marqueur est globale, result pointe sur l'unique resultat de main.

Récursivité et itération diapos 47–51

Une boucle peut toujours remplacer la récursivité, et réciproquement. La question est de savoir laquelle choisir.

Propriété

Tout algorithme récursif peut être transformé en algorithme itératif, et réciproquement.

int fact(int n)
{
   if (n == 1)
        return 1;
   return n*fact(n-1);
}
int fact(int n)
{
   int res;
   res = n;
   while(n!=1){
       n = n - 1;
       res = res*n;
   }
   return res;
}

Version récursive

  • Plus naturelle quand on part d'une définition récursive.
  • Plus simple en cas de récursivité multiple (parcours d'arbres).
  • Elle s'impose en programmation fonctionnelle (Lisp, Caml, Haskell) ou déclarative (Prolog).

Version itérative

  • Beaucoup plus économique à l'exécution : pas de duplication de la fonction ni de ses variables.

Bilan : en programmation impérative, on cherche un compromis entre la simplicité de l'algorithme et son coût d'exécution, et l'on préfère en général la version itérative, pour son efficacité.

Dérécursivation diapos 52–64

Transformer un algorithme récursif en un algorithme itératif équivalent s'appelle la dérécursivation. La méthode dépend du type de récursivité.

Définition Récursivité terminale

Un algorithme est récursif terminal s'il ne contient aucun traitement après l'appel récursif. Il est récursif non terminal s'il effectue un traitement après un appel récursif.

fact2 est récursive terminale : le résultat de fact2(n-1, n*result) est renvoyé tel quel. fact ne l'est pas : elle multiplie par n après l'appel.

Le cas terminal

Forme récursive terminale

type f_rec(params)
     if (condition)
           traitement1
     else
     {
           traitement2
           f_rec(nouv_params)
     }

Forme itérative équivalente

type f_iter(params)
     while (non condition)
     {
           traitement2
           params = nouv_params
     }
     traitement1

Sur fact2 : la condition est n == 1, traitement1 est return result, traitement2 est vide, et les nouveaux paramètres sont (n-1, n*result).

Attention La version itérative de la diapo 58 À vérifier

Les diapos donnent :

int fact2_iter(int n, int result)
{
       while (n!=1)
       {
             n = n - 1;
             result = result*n;
       }
       return result;
}

Exécutée, fact2_iter(3,1) renvoie 2 et fact2_iter(5,1) renvoie 24 : on obtient \((n-1)!\). Les deux affectations doivent reprendre params = nouv_params avec les anciennes valeurs : result prend n*result avant que n diminue.

int fact2_iter(int n, int result)
{
       while (n!=1)
       {
             result = n*result;   /* nouveau result, avec l'ancien n */
             n = n - 1;
       }
       return result;
}

Cette version renvoie bien 6 pour fact2_iter(3,1). La version itérative de fact (diapo 48) est juste, elle, parce qu'elle part de res = n.

Le cas non terminal

type f_rec(params)
      if (condition)
             traitement1
      else
      {
             traitement2
             f_rec(nouv_params)
             traitement3(nouv_params)
      }

Méthode Dérécursiver une fonction non terminale

  1. Première méthode : transformer la fonction en fonction récursive terminale, puis se ramener au cas précédent. Il faut en général ajouter un paramètre, comme l'accumulateur de fact(int n) → fact2(int n, int result).
  2. Deuxième méthode, quand la transformation n'est pas possible (récursivité multiple) : introduire une pile où l'on range les paramètres des appels récursifs. Elle est plus complexe à réaliser.

Tri rapide récursif

void quicksort(i,j)
{
  int m ; /* milieu */
  if(i<j){
    m = partition(i,j);
    quicksort(i,m-1);
    quicksort(m+1,j);
  }
}

Avec une pile

void quicksort(i,j)
{
  empiler(0,N-1);
  while(!pilevide()){
    depiler(i,j);
    if(i<j){
      m = partition(i,j);
      empiler(i,m-1);
      empiler(m+1,j);
    }
  }
}

La pile remplace la pile d'exécution : au lieu d'appeler quicksort sur les deux moitiés, on note les deux intervalles à trier, et la boucle les traite tant qu'il en reste. L'ordre de traitement change, mais chaque intervalle est bien partitionné.

Les types de récursivité diapos 65–89

Au-delà de la récursivité simple (un seul appel, comme fact), on distingue trois formes : multiple, mutuelle (ou croisée) et imbriquée.

La récursivité multiple

Définition

Une fonction est à récursivité multiple quand elle effectue plusieurs appels récursifs consécutifs.

Le nombre de combinaisons : \(C_n^p = 1\) si \(p = 0\) ou \(p = n\), et \(C_n^p = C_{n-1}^p + C_{n-1}^{p-1}\) sinon.

/* calcule récursivement Cnp */
int comb(int n, int p)
{
  if (p == 0 || p == n)
       return 1;
  else
       return comb(n-1,p) + comb(n-1,p-1);
}

Application Dérouler comb(3,2)

Dérouler l'exécution de comb(3,2) en faisant apparaître chaque appel récursif, et donner le résultat.

Correction

comb(3,2) = comb(2,2) + comb(2,1) = 1 + (comb(1,1) + comb(1,0)) = 1 + (1 + 1) = 3.

Complément Le coût de la récursivité multiple

Les deux appels recalculent souvent les mêmes valeurs : comb(n, n/2) fait un nombre d'appels de l'ordre de \(C_n^{n/2}\), qui croît exponentiellement avec \(n\). Mémoriser les valeurs déjà calculées dans un tableau (triangle de Pascal) ramène le calcul à \(O(n \times p)\) opérations.

La récursivité mutuelle

Définition

Des définitions sont mutuellement récursives (récursivité croisée) quand elles dépendent l'une de l'autre.

Le « cas d'école » de la parité : \(n\) est pair si \(n = 0\) ou si \(n - 1\) est impair ; \(n\) est impair si \(n = 1\) ou si \(n - 1\) est pair.

int pair(int n){
        if(n==0)
                 return vrai;
        else
                 return impair(n-1);
}

int impair(int n){
       if(n==0)
                return faux;
       else
                return pair(n-1);
}

Note Pour compiler Ajout

En C, impair doit être déclarée avant d'être appelée dans pair : on écrit son prototype int impair(int n); en tête. vrai et faux ne sont pas des mots du C : #define vrai 1 et #define faux 0, ou true et false de <stdbool.h>. Le code teste n == 0 dans impair (« 0 n'est pas impair ») au lieu de n == 1 de la définition : les deux conviennent pour \(n \ge 0\).

Application pair(3) et pair(2)

Dérouler l'exécution de pair(3) et de pair(2) en faisant apparaître chaque appel récursif, et donner le résultat.

Correction 
3 est-il pair ?                 2 est-il pair ?
pair(3)        faux             pair(2)        vrai
  ↓             ↑                 ↓             ↑
impair(2)      faux             impair(1)      vrai
  ↓             ↑                 ↓             ↑
pair(1)        faux             pair(0)   →    vrai
  ↓             ↑
impair(0)  →   faux

La valeur du cas immédiat remonte telle quelle : ces fonctions sont récursives terminales.

La récursivité imbriquée

Définition

Une récursivité est imbriquée quand un paramètre de l'appel récursif est lui-même issu d'un appel récursif.

La fonction d'Ackermann : (a) \(A(m,n) = n + 1\) si \(m = 0\) ; (b) \(A(m,n) = A(m-1, 1)\) si \(m \gt 0\) et \(n = 0\) ; (c) \(A(m,n) = A(m-1, A(m, n-1))\) sinon.

int ack(int m, int n)
{
      if (m==0)
             return n+1;
      else if (m>0 && n==0)
             return ack(m-1,1);
      else
             return ack(m-1, ack(m,n-1));
}

Application Dérouler ack(1,1)

Dérouler l'exécution de ack(1,1) en faisant apparaître chaque appel récursif, et donner le résultat.

Correction 
ack(1,1)
   │ (c)
ack(0, ack(1,0))  →  ack(0,2) = 3   (a)
          │ (b)
       ack(0,1) = 2   (a)

ack(1,1) = 3

Il faut d'abord calculer l'argument intérieur ack(1,0), qui vaut ack(0,1) = 2, avant de pouvoir lancer l'appel extérieur ack(0,2) = 3.

Complément Une croissance explosive

La fonction d'Ackermann croît plus vite que toute fonction que l'on peut écrire avec des boucles for à bornes fixées : \(A(2,n) = 2n + 3\), \(A(3,n) = 2^{n+3} - 3\), et \(A(4,2)\) a 19 729 chiffres. Elle sert d'exemple de fonction calculable qui n'est pas « primitive récursive ».

À retenir

L'essentiel

  • Une fonction récursive s'appelle elle-même ; elle a un cas immédiat, que chaque appel doit rapprocher, et un cas récursif.
  • Chaque appel a ses propres paramètres et variables locales ; les variables globales, et les objets désignés par des pointeurs, sont partagés.
  • fact calcule au retour des appels ; fact2, avec un accumulateur, calcule au moment des appels.
  • Récursivité terminale : aucun traitement après l'appel ; elle devient une boucle while (non condition) { traitement2 ; params = nouv_params ; } traitement1.
  • Dérécursiver une fonction non terminale : ajouter un paramètre pour la rendre terminale, ou, en récursivité multiple, gérer une pile de paramètres.
  • Récursif : plus naturel et plus simple sur les arbres ; itératif : plus économique, préféré en programmation impérative.
  • Récursivité multiple (plusieurs appels, comb), mutuelle (pair et impair), imbriquée (un appel en argument d'un appel, Ackermann).

Auto-évaluation

fact est-elle récursive terminale ? Et fact2 ?

fact non : elle multiplie par n après l'appel. fact2 oui : elle renvoie directement le résultat de l'appel récursif.

Combien d'exemplaires du paramètre n existent pendant l'appel de fact(1) lancé par fact(4) ?

Quatre : 4, 3, 2 et 1, un par appel en cours.

Que renvoie comb(4,2), et combien d'appels fait-il en tout ?

6 ; il fait 11 appels : comb(4,2), puis comb(3,2) (5 appels, comme dans l'exemple) et comb(3,1) (5 appels).

Pourquoi le tri rapide ne se dérécursive-t-il pas par un simple accumulateur ?

Il fait deux appels récursifs (récursivité multiple) : il faut se souvenir du second intervalle pendant qu'on traite le premier, d'où une pile.

Que vaut ack(2,1) ?

5 (\(A(2,n) = 2n + 3\)).

Pourquoi le programme du marqueur utilise-t-il une variable locale x et une variable globale marqueur ?

Chaque valeur lue doit être gardée jusqu'à ce que l'opérateur soit connu, un exemplaire par appel ; l'opérateur, lui, est unique et doit être vu de tous les appels.
