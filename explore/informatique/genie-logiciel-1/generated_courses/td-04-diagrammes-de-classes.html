Objectifs

  • Choisir entre généralisation, composition, agrégation et association.
  • Passer d'un modèle entité-association, d'un texte ou d'un diagramme d'objets à un diagramme de classes.
  • Utiliser une classe d'association, et savoir quand elle ne convient pas.
  • Lire un diagramme de classes pour décider si un diagramme d'objets lui est conforme.

Notions utilisées

  • Cours 4 : diagrammes de classes, multiplicités, agrégation, composition, héritage, correspondance avec le modèle entité-association.
  • Cours 1 de bases de données : classes d'association.

Depuis un modèle entité-association

Exercice 1 Phrase 1, modèle A

Dans cet exemple, Comp_Aero modélise tous les couples sans doublons (compagnie, aéroport) qui sont considérés comme valides (à savoir la localisation des compagnies dans chaque aéroport). À chaque couple des attributs peuvent être associés : ici, la date d'arrivée d'une compagnie dans un aéroport et le nombre de comptoirs dont elle dispose.

On peut noter que les deux attributs de cette classe ne peuvent pas être disposés ailleurs. Cette date d'arrivée ne dépend pas non plus de l'aéroport seul, car Orly qui a accueilli Air France en 1967 a vu débarquer Air Liberté en 1990.

Réservation de vols TD, p. 2–3

Cette étude de cas concerne un système simplifié de réservation de vols pour une agence de voyages. Les interviews des experts métier auxquelles on a procédé ont permis de résumer leur connaissance du domaine sous la forme des phrases suivantes :

  4. Une réservation concerne un seul vol et un seul passager.
  5. Une réservation peut être annulée ou confirmée.
  6. Un vol a un aéroport de départ et un aéroport d'arrivée.
  7. Un vol a un jour et une heure de départ et un jour et une heure d'arrivée.
  8. Un vol peut comporter des escales dans des aéroports.
  9. Une escale a une heure d'arrivée et une heure de départ.
  10. Chaque aéroport dessert une ou plusieurs villes.

D'une classe Java à sa représentation TD, p. 4–5

Exercice 6 Représentation graphique d'une classe Java

Donner une représentation graphique de la classe PointPlan suivante.

public class PointPlan {

    private float abscisse;
    private float ordonnee;

    public PointPlan() {
        this.abscisse = 0 ;
        this.ordonnee = 0 ;
    }
    public PointPlan(float x, float y) {
        this.abscisse = x ;
        this.ordonnee = y ;
    }
    public PointPlan(PointPlan p) {
        this.abscisse = p.getAbscisse() ;
        this.ordonnee = p.getOrdonnee() ;
    }
    private float getOrdonnee() {
        return this.ordonnee ;
    }
    private float getAbscisse() {
        return this.abscisse ;
    }
    public boolean egaleA (PointPlan p) {
        return (this.getAbscisse() == p.getAbscisse()
                && this.getOrdonnee() ==  p.getOrdonnee()) ;
    }
    public void init() {
        Scanner input = new Scanner(System.in);
        System.out.print("Abscisse ? ") ;
        this.abscisse = input.nextInt();
        System.out.print("Ordonnée ? ") ;
        this.ordonnee = input.nextInt();
    }
    public void translate(float dx, float dy) {
        this.abscisse = this.abscisse + dx ;
        this.ordonnee = this.ordonnee + dy ;
    }
    public double distance() {
        return Math.sqrt(this.abscisse * this.abscisse +
                         this.ordonnee * this.ordonnee) ;
    }
    public String toString() {
        return "(" + this.getAbscisse() + "," + this.getOrdonnee() + ")";
    }
    public void affiche() {
        System.out.println(this.toString()) ;
    }
}

À retenir

Les méthodes

  • « Est une sorte de » : généralisation. « Est composé de », avec des parties propres : composition ; avec des parties partageables : agrégation. Sinon : association.
  • Un même mot peut cacher deux relations : « un répertoire contient des fichiers qui peuvent être des documents » donne une composition et un héritage.
  • Un attribut qui dépend d'un couple d'objets va dans une classe d'association. Elle n'existe qu'une fois par couple : s'il faut plusieurs objets pour un même couple, on prend une classe ordinaire.
  • Deux associations binaires ne remplacent pas une relation entre trois classes : il faut un objet qui les relie (phrase 6).
  • Le patron composite modélise une structure récursive : la classe mère commune permet au conteneur de contenir aussi des conteneurs.
  • Pour rendre une contrainte impossible à violer, on la met dans la structure (les opérandes de l'exercice 3) plutôt que dans une multiplicité 0..1.
  • Conforme signifie que chaque objet et chaque lien existent dans le diagramme de classes : seule une classe qui porte l'association peut l'utiliser.

Auto-évaluation

Agrégation ou composition : une pièce et ses murs ? un répertoire et ses fichiers ?

Pièce et murs : agrégation, car un mur peut séparer deux pièces. Répertoire et fichiers : composition, car un fichier est dans un seul répertoire et disparaît avec lui.

Quand une classe d'association ne convient-elle pas ?

Quand il faut plusieurs objets pour un même couple : elle n'existe qu'une fois par couple. On prend alors une classe ordinaire, reliée aux deux autres. La correction du cinéma garde la classe d'association, car l'énoncé ne demande pas plusieurs séances : voir la phrase 12.

Où se place la multiplicité en UML, par rapport à la cardinalité d'un modèle E/A ?

Du côté opposé : la multiplicité UML est près de la classe dont on compte les objets, la cardinalité E/A près de l'entité qui participe.

Comment voir sur un diagramme d'objets qu'il y a composition ou partage ?

Si deux tout sont reliés au même objet, il y a partage : agrégation. Deux objets de mêmes valeurs mais distincts ne sont pas partagés.
