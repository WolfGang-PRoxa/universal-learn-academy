Base de données Univ p. 1–2

Rappel du modèle (diagramme de classes)

Modèle relationnel (MR) correspondant :

PERS (id_pers, prenom, nom)

PROF (#id_prof(id_pers), date_arr)

PROMO (id_promo, nom_niveau, nom_filiere, nom_ufr)

SCOLARITE (#id_promo, annee, #id_etudiant(id_pers), moyenne)

MODULE (id_module, nom_module, dsc_module)

ENSEIGNEMENT (#id_promo, #id_prof(id_pers), annee, #id_module)

Les attributs soulignés forment la clé primaire de chaque relation.

Implémentation

  1. Implémentez la base de données Univ en suivant les conseils et indications :
    1. Suivez bien les noms et ordres des attributs du MR (contrôlez le script d'insertion des données).
    2. Vous penserez bien évidemment aux clés primaires et clés étrangères.
    3. N'ayez pas la main trop lourde sur les not null…
    4. Module, Promo et Pers doivent avoir des clés primaires de type SERIAL.
    5. Limitez le descriptif du module à 200 caractères.
    6. L'année est un entier qui doit être compris entre 2000 et 2150.
    7. Le niveau de la promo doit commencer par « L », « M » ou « D » suivi de « 1 », « 2 » ou « 3 ».

      Aide : vous vous rendez compte qu'avec des LIKE, ceci entraîne 6 tests ! Pourquoi ne pas essayer le SIMILAR TO qui est très bien expliqué sur la doc postgre ?

Modification

Vous vous êtes rendu compte que 2 faits ne sont pas modifiables dans votre base :

  1. Un étudiant ne peut pas être AJAC, c'est-à-dire avoir 2 moyennes pour une année donnée.
  2. Un prof ne peut pas enseigner plusieurs modules à une promo la même année.

Modifiez votre base pour que ces deux phénomènes soient possibles.

  1. La table enseignement a un nom trop long… modifiez-le en ens.
  2. L'attribut moyenne a un nom trop long… modifiez-le en moy.

Chez soi : la console SQL du TP

La console ci-dessous exécute le compte rendu entier sur une base PostgreSQL neuve (PGlite), par le serveur local : studies/lancer.bat, puis cette page ouverte depuis le portail. Sans le serveur, on peut écrire, mais pas exécuter.

  1. Les réponses s'écrivent dans l'ordre des questions ; le script fourni est déjà en place, à la question 6f.
  2. Exécuter (ou Ctrl + Entrée) rejoue tout, depuis le début, sur une base neuve, et affiche le résultat de la dernière requête qui renvoie des lignes, ou la première erreur. Pour voir le résultat d'une question, on la met en dernier, ou on met en commentaire (--) les requêtes qui suivent.
  3. Le travail s'enregistre tout seul : dans le navigateur, et, avec le serveur, dans le dossier td_results/ de ce cours, dans ton espace. Le menu ⋯ copie le texte, à coller dans TP3_NOM_PRENOM.txt.

Attention Ce qui change par rapport à la fac

  • Le script fourni n'est inséré qu'une fois les tables créées, renommées (questions 4 et 5 : il écrit dans ens) et les premières données en place (6a à 6e) : tant que ces questions sont vides, l'exécution s'arrête sur lui.
  • L'heure (question 8) est celle de l'ordinateur ; tout est rejoué à chaque exécution, donc les insertions ajoutées pour tester valent pour toutes les requêtes qui les suivent.

À retenir

Les méthodes

  • L'ordre et les noms des attributs sont imposés par le MR et par le script fourni : le relire avant de créer les tables.
  • Une contrainte de domaine (intervalle, motif, longueur) se déclare avec la table : le SGBD refuse ensuite toute valeur hors domaine.
  • Une clé primaire traduit une règle de gestion : la changer change ce que la base accepte (questions 2 et 3).
  • Le script fourni retrouve les identifiants par des sous-requêtes sur les noms : les noms insérés doivent être exactement ceux qu'il cherche.
  • Un étudiant figure une fois par année dans la scolarité : compter des étudiants n'est pas compter des lignes.

Auto-évaluation

Pourquoi l'ordre des attributs compte-t-il ici ?

Le script fourni insère avec VALUES sans nommer les colonnes (sauf pour pers) : les valeurs vont dans les colonnes dans l'ordre de la table.

Pourquoi une sous-requête du script peut-elle insérer NULL sans erreur ?

Une sous-requête qui ne trouve aucune ligne vaut NULL : l'insertion passe si la colonne l'accepte, et la ligne est fausse sans qu'on le voie.

Que faut-il compter pour « le nombre d'étudiants » ?

Les personnes distinctes de la scolarité, pas ses lignes : un étudiant y figure une fois par année.

Quelle différence entre WHERE et HAVING ?

WHERE filtre les lignes avant le regroupement, HAVING filtre les groupes, après.
