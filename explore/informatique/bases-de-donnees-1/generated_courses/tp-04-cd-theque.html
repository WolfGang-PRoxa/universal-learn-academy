Base de données CD p. 1

Rappel du modèle entité-association (version sans classe Musique)

Sur la figure du sujet, les multiplicités de « appartient » sont entre parenthèses, (1..1) près de CD et (1..*) près de Enr : un enregistrement est identifié relativement à son CD. La multiplicité « 1..n » de « est composé par » est notée 1..* ici.

Rappel du modèle relationnel associé

PERSONNE (id_pers, nom_pers, prenom_pers, date_nais, date_deces, pays_nationalite)

EDIT (id_edit, nom_edit, pays)

CD (id_cd, titre_cd, #id_edit, note_art, note_tech, nom_distrib)

ENREG (#id_cd, id_enr, titre_enr, duree_enr, annee_enr, lieu_enr, cond_enr)

INTERP (#id_cd, #id_enr, #id_interprete(id_pers), instrument)

LEADER (#id_cd, #id_leader(id_pers))

COMPO (#id_cd, #id_enr, #id_compo(id_pers))

Les clés primaires, en gras dans le sujet, sont soulignées ici. Le script fourni nomme la table des éditeurs edition, et non edit.

La console ci-dessous exécute le compte rendu entier sur une base PostgreSQL neuve (PGlite), par le serveur local : studies/lancer.bat, puis cette page ouverte depuis le portail. Sans le serveur, on peut écrire, mais pas exécuter.

  2. Exécuter (ou Ctrl + Entrée) rejoue tout, depuis le début, sur une base neuve, et affiche le résultat de la dernière requête qui renvoie des lignes, ou la première erreur. Pour voir le résultat d'une question, on la met en dernier, ou on met en commentaire (--) les requêtes qui suivent.
  3. Le travail s'enregistre tout seul : dans le navigateur, et, avec le serveur, dans le dossier td_results/ de ce cours, dans ton espace. Le menu ⋯ copie le texte, à coller dans TP4_NOM_PRENOM.txt.

Attention Ce qui change par rapport à la fac

  • Tant que la table compo n'est pas écrite, l'exécution s'arrête sur la première insertion dans compo.
  • \i, \d et les autres commandes de psql ne sont pas du SQL : la console les refuse.
  • Tout est rejoué à chaque exécution : les modifications (questions 3, 7, 16, 17, 20) valent pour toutes les requêtes qui les suivent, comme à la fac.

À retenir

Les méthodes

  • Un enregistrement est identifié relativement à son CD : toute table qui le référence le fait par le couple (id_cd, id_enr), jamais par id_cd seul.
  • Le script fourni crée les tables dans l'ordre des références et insère sans nommer les colonnes : la table ajoutée doit respecter cet ordre et cet emplacement.
  • Une contrainte ajoutée après coup ne passe que si les données déjà présentes la respectent.
  • Restructurer sans perte : créer la nouvelle table, la remplir à partir des données existantes, raccrocher les anciennes tables par de nouvelles clés étrangères, vérifier, et seulement alors supprimer les colonnes devenues inutiles.
  • Une requête qui dépend de la date du jour (« depuis moins de 20 ans ») ne donne pas le même résultat d'une année à l'autre.

Auto-évaluation

Pourquoi id_cd seul ne doit-il pas référencer CD dans compo ?

Un compositeur compose un enregistrement, pas un CD : la référence doit désigner une plage précise, donc le couple (id_cd, id_enr) d'ENREG.

Où placer la création de compo dans le script, et pourquoi ?

À l'emplacement prévu, après ENREG et PERSONNE qu'elle référence, et avant les insertions dans compo.

Quel défaut la table MUSIQUE corrige-t-elle ?

Les compositeurs d'un morceau étaient saisis à chaque enregistrement de ce morceau : une redondance, source d'incohérences.

Que faut-il compter pour « le nombre d'instruments différents par enregistrement » ?

Les instruments distincts par couple (id_cd, id_enr) : un enregistrement n'est identifié que par les deux.
