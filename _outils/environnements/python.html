Les notebooks Python sous Windows et sous Linux

Plusieurs matières se travaillent dans des notebooks Jupyter : les exemples des cours, le devoir maison de Mathématiques et IA, des TP. Plutôt qu'un environnement par matière, un seul environnement Python les sert tous. Il s'installe hors de Google Drive, se met à jour tout seul, et s'ouvre par un lanceur à la racine de studies, le même sous Windows et sous Linux.

Objectifs

  • Ouvrir un notebook du dépôt avec lancer-jupyter.bat (Windows) ou lancer-jupyter.sh (Linux).
  • Savoir ce que contient l'environnement, où il se trouve et comment lui ajouter une bibliothèque.
  • Reconnaître les erreurs d'environnement les plus fréquentes.

Prérequis

  • Ouvrir un terminal : cmd ou PowerShell sous Windows, bash sous Linux.
  • Avoir un Python 3 installé (c'est le cas sur le PC).

Un environnement commun, hors du Drive

Un environnement virtuel (virtual environment, module venv) est un dossier qui contient son propre Python et ses propres bibliothèques, indépendants du Python du système. Celui des notebooks est décrit par un seul fichier, versionné avec le dépôt.

_outils/environnements/python/requirements.txt
la liste des bibliothèques, au format de pip : Jupyter (notebook, ipykernel), numpy, scipy, pandas, scikit-learn, networkx (TP de théorie des graphes), matplotlib, seaborn, tqdm et opensmile (descripteurs audio du devoir maison).
lancer-jupyter.bat, lancer-jupyter.sh
les lanceurs, à la racine de studies, à côté de lancer.bat (serveur des quiz) et lancer-app.bat (application Studies).

L'environnement lui-même n'est pas dans le dépôt : il pèse près de 800 Mo et contient des milliers de petits fichiers, que Google Drive mettrait des heures à synchroniser. Il va dans le dossier local de l'utilisateur.

Où va l'environnement
Système Dossier Python de l'environnement
Windows %LOCALAPPDATA%\studies-python Scripts\python.exe
Linux ~/.local/share/studies-python bin/python

Méthode Ce que fait le lanceur

  1. Si l'environnement n'existe pas, il le crée avec le Python du système : py -3, à défaut python, sous Windows ; python3 sous Linux.
  2. Si requirements.txt diffère de la copie gardée dans l'environnement, il installe les bibliothèques avec pip, puis met la copie à jour. Sinon, il ne fait rien : un lancement ordinaire est immédiat.
  3. Il ouvre Jupyter, sur la racine de studies, sur le dossier ou sur le notebook donné.

Attention À lancer une fois soi-même

L'essai a été fait depuis l'application Claude, que Windows isole : son %LOCALAPPDATA% est redirigé vers %LOCALAPPDATA%\Packages\Claude_…\LocalCache\Local. L'environnement installé ce jour-là n'est visible que des programmes lancés depuis Claude. Il faut donc lancer une première fois lancer-jupyter.bat soi-même, d'un double-clic, pour installer le vrai (moins de deux minutes). La copie isolée (environ 760 Mo) peut ensuite être supprimée.

Ouvrir un notebook

Les deux lanceurs prennent les mêmes arguments. Sans argument, Jupyter s'ouvre sur la racine de studies ; avec un dossier, sur ce dossier ; avec un notebook, sur la racine, le notebook déjà ouvert.

Sous Windows

Double-cliquer sur lancer-jupyter.bat, ou glisser un notebook dessus. Dans un terminal :

$ cd "C:\Users\piaur\prog\ula"
$ lancer-jupyter.bat romain\L3\AI_maths\DM\script.ipynb

La fenêtre du lanceur reste ouverte tant que Jupyter tourne : la fermer arrête Jupyter. En cas d'erreur, elle attend une touche, pour laisser lire le message.

Sous Linux

$ cd studies
$ ./lancer-jupyter.sh romain/L3/AI_maths/DM/script.ipynb

Ctrl+C arrête Jupyter. Les arguments qui suivent le notebook vont à Jupyter, par exemple --no-browser sur une machine distante. Sur une machine de la fac, l'environnement s'installe dans le compte de l'utilisateur, sans droit d'administrateur ; il faut seulement que Python ait le module venv (sous Ubuntu, paquet python3-venv).

Installer sans ouvrir Jupyter

$ lancer-jupyter.bat --installer
Environnement pret : C:\Users\piaur\AppData\Local\studies-python
Python 3.11.9

Utile avant une séance sans réseau, ou pour vérifier que tout s'installe. ./lancer-jupyter.sh --installer fait de même sous Linux.

Remarque Le dossier de travail d'un notebook

Jupyter exécute chaque notebook dans le dossier où il se trouve. Un notebook qui lit pd.read_csv('donnees.csv') trouve donc le fichier posé à côté de lui, quel que soit le dossier d'où l'on a lancé Jupyter.

Ajouter une bibliothèque

Une bibliothèque qui manque à un notebook s'ajoute à requirements.txt, une par ligne, puis on relance le lanceur : il voit que le fichier a changé et l'installe. Ainsi, le PC, la fac et un nouvel ordinateur ont toujours le même environnement.

Astuce Essayer avant d'ajouter

Pour un essai ponctuel, une cellule %pip install nom installe la bibliothèque dans l'environnement du noyau en cours. Elle disparaîtra à la prochaine réinstallation complète si elle n'est pas dans requirements.txt.

Pour repartir de zéro, il suffit de supprimer le dossier de l'environnement (%LOCALAPPDATA%\studies-python) : le lanceur le recrée au lancement suivant.

Le serveur des quiz (lancer.bat) utilise aussi cet environnement pour les questions de code Python quand il existe : numpy et pandas y sont disponibles. Sinon, il prend le Python du système.

Les deux premiers messages sont ceux des lanceurs ; les autres viennent de Python et de Jupyter.

À retenir

L'essentiel

  • Un seul environnement Python sert tous les notebooks du dépôt ; il est décrit par _outils/environnements/python/requirements.txt.
  • lancer-jupyter.bat (Windows) et ./lancer-jupyter.sh (Linux) le créent, le mettent à jour et ouvrent Jupyter.
  • L'environnement vit hors du Drive : %LOCALAPPDATA%\studies-python sous Windows, ~/.local/share/studies-python sous Linux.
  • On glisse un notebook sur lancer-jupyter.bat pour l'ouvrir directement.
  • Une bibliothèque de plus : une ligne dans requirements.txt, puis relancer.
  • Un notebook s'exécute dans son propre dossier : ses fichiers de données se posent à côté de lui.

Auto-évaluation

Pourquoi l'environnement n'est-il pas dans le dossier studies ?

Parce que studies est sur Google Drive : les milliers de fichiers de l'environnement (près de 800 Mo) seraient synchronisés sans fin, et un environnement virtuel ne se déplace pas d'un ordinateur à l'autre. Seul requirements.txt, qui le décrit, est versionné.

On ajoute sympy à requirements.txt. Que se passe-t-il au lancement suivant ?

Le lanceur voit que le fichier diffère de la copie gardée dans l'environnement : il lance pip install -r requirements.txt, qui n'installe que ce qui manque, puis met la copie à jour.

Pourquoi le lanceur Windows essaie-t-il py -3 avant python ?

Parce que python peut n'être que le raccourci du Microsoft Store, qui ouvre le Store au lieu de lancer Python. py est le lanceur installé avec Python par python.org.

Comment repartir d'un environnement propre ?

Supprimer le dossier studies-python (dans %LOCALAPPDATA% ou ~/.local/share) et relancer : le lanceur le recrée et réinstalle tout.
