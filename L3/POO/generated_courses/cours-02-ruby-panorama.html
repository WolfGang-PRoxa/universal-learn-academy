Ruby, panorama

Ruby est le langage des TD et des TP du module : un langage où tout est objet, et où programmer revient à envoyer des messages à des objets. Complément Typage statique, typage dynamique

Dans un langage à typage statique (static typing), chaque variable a un type fixé dans le texte du programme, et le compilateur refuse d'y ranger une valeur d'un autre type. En C, int x = 12; suivi de x = "titi"; ne compile pas.

Dans un langage à typage dynamique (dynamic typing), ce sont les valeurs qui ont un type, pas les variables. En Ruby, x = 12 puis x = "titi" est accepté : la variable désigne simplement un autre objet. Les erreurs de type apparaissent à l'exécution, quand un objet reçoit un message qu'il ne comprend pas (section 4.8).

Ruby et Smalltalk p. 4

Smalltalk aurait été une alternative pédagogique naturelle. Mais si Smalltalk est un petit langage, c'est aussi un gros système : il faut compter environ 9 mois pour être opérationnel et 18 mois pour devenir expert, contre 3 à 5 ans en C++. Ruby est plus petit et plus facile à apprendre.

Ruby en une formule

Ruby = Smalltalk − syntaxe inhabituelle + scripts à la Perl + gestion des erreurs + itérateurs (issus de CLU) + de nombreux autres outils.

Autrement dit : Ruby > (Smalltalk + Perl) / 2.

Yukihiro « Matz » Matsumoto résume sa philosophie ainsi :

Les langages « jouets » ne sont pas bons. Ils peuvent résoudre de petits problèmes, mais les langages réels résolvent les mêmes problèmes d'une meilleure façon.

Complément Les ancêtres cités dans la formule

  • Smalltalk (Xerox PARC, années 1970) est le langage qui a fixé le modèle repris par Ruby : tout est objet, et un programme s'exécute par envoi de messages entre objets.
  • Perl est un langage de scripts conçu pour traiter du texte. Ruby lui emprunte les expressions régulières intégrées au langage (section 8.2) et les variables globales prédéfinies comme $_ (section 5.6).
  • CLU (MIT, années 1970) a introduit les itérateurs : une méthode qui fournit les éléments d'une collection un par un à un bloc de code. Le each de la section 2.1 en est un ; ils sont étudiés au cours 4.

Étude de cas : la factorielle en C, Java et Ruby p. 4–7

Le même programme, qui calcule et affiche \(n!\) pour \(n\) de 1 à 39 avec une version récursive, révèle des différences profondes entre les trois langages.

Trois versions du même programme p. 5–6

En C, la fonction facto travaille sur des entiers long. Le programme se compile avec gcc, puis s'exécute.

#include<stdio.h>

/* Définition de la factorielle de n
   Version récursive, condition d'arrêt 0 */
long facto(long n) {
    if (!n)
        return 1;
    else
        return n * facto(n - 1);
}

/* Programme de test : factorielle des nombres de 1 à 39 */
int main() {
    for (int i = 1; i < 40; i++)
        printf("La Factorielle de %d est %ld\n", i, facto(i));
}
$ gcc -o facto facto.c
$ ./facto

La version Java a la même structure, dans une classe Facto dont les deux méthodes sont statiques. Ajout On la compile avec javac Facto.java et on l'exécute avec java Facto.

/* Définition de la factorielle de n
 * Version récursive, condition d'arrêt 0
 */
public class Facto {

    public static long facto(long n) {
        if (n == 0) {
            return 1;
        } else {
            return n * facto(n - 1);
        }
    }

    /* Programme de test : factorielle des nombres de 1 à 39 */
    public static void main(String[] args) {
        for (int i = 1; i < 40; i++) {
            System.out.printf("La Factorielle de %d est %d%n", i, facto(i));
        }
    }
}

La version Ruby ne déclare aucun type et n'a pas besoin de return.

# Définition de la factorielle de n
# Version récursive, condition d'arrêt 0
def facto(n)
  if n == 0
    1
  else
    n * facto(n - 1)
  end
end

# Programme de test : factorielle des nombres de 1 à 39
(1...40).each do |i|
  puts "La Factorielle de #{i} est #{facto(i)}"
end

Complément Lire la version Ruby

  • def facto(n) … end définit une méthode. Le paramètre n n'a pas de type, et la méthode non plus.
  • Il n'y a pas de return : une méthode retourne la valeur de la dernière expression évaluée, ici 1 ou n * facto(n - 1) (section 4.6).
  • 1...40 est un intervalle (range), un objet de la classe Range. Avec trois points, la borne supérieure est exclue (1 à 39) ; avec deux points, 1..40, elle est incluse (1 à 40).
  • each est un message envoyé à l'intervalle. Il exécute le bloc do |i| … end une fois par élément, en liant i à cet élément : c'est un itérateur, étudié au cours 4.
  • Dans une chaîne entre guillemets, #{…} insère la valeur d'une expression (section 8.1). puts affiche la chaîne suivie d'un retour à la ligne.

Attention Dépassement de capacité silencieux

En C comme en Java, le résultat dépasse la capacité d'un long : c'est un dépassement de capacité (overflow). Les nombres obtenus n'ont aucune signification, mais le programme ne plante pas et ne prévient pas. Dans un programme plus important, les conséquences peuvent être graves, et le bug difficile à détecter et à corriger.

Complément Pourquoi la limite est-elle 20! ?

Un long Java, comme un long C sous Linux ou macOS, occupe 64 bits en complément à deux. La plus grande valeur représentable est \(2^{63} - 1 \approx 9{,}22 \times 10^{18}\). Or \(20! \approx 2{,}43 \times 10^{18}\) tient, alors que \(21! \approx 5{,}11 \times 10^{19}\) ne tient plus.

Le calcul garde seulement les 64 bits de poids faible du vrai résultat, et les lit comme un nombre signé : \(21! - 3 \times 2^{64} = -4\,249\,290\,049\,419\,214\,848\), la valeur du tableau. Java garantit ce comportement « modulo \(2^{64}\) ». En C, le dépassement d'un entier signé est un comportement indéfini : la norme n'impose aucun résultat.

La taille d'un long C dépend en outre de la plate-forme. Sous Windows, il ne fait que 32 bits : compilé avec gcc 10.3 sous Windows, facto.c affiche 1932053504 pour 13!, qui vaut 6227020800, et 0 pour 39!. Les valeurs C du tableau sont celles d'un système 64 bits de type Unix.

La solution en Java : des entiers « plus gros »

Il faut d'abord penser au problème, puis utiliser des objets entiers de précision arbitraire, de la classe BigInteger. Ruby gère cette situation automatiquement.

import java.math.BigInteger;

public class FactoBig {

    public static BigInteger facto(BigInteger n) {
        if (n.equals(BigInteger.ZERO)) {
            return BigInteger.ONE;
        } else {
            return n.multiply(facto(n.subtract(BigInteger.ONE)));
        }
    }

    public static void main(String[] args) {
        for (int i = 1; i < 40; i++) {
            System.out.printf("La Factorielle de %d est %s%n", i, facto(BigInteger.valueOf(i)));
        }
    }
}

Les résultats sont alors identiques à ceux de Ruby. On remarque le prix à payer en Java : chaque opération devient un envoi de message (multiply, subtract, equals), alors qu'en Ruby on continue d'écrire n * facto(n - 1).

Complément Les entiers de Ruby

En Ruby, un entier est un objet de la classe Integer, de précision arbitraire : l'interpréteur passe tout seul d'une représentation machine à une représentation en grand nombre quand la valeur grandit. 2**100 vaut 1267650600228229401496703205376, et (2**100).class répond Integer.

Limite de la pile d'exécution p. 7

RDoc p. 8–9

Mieux encore, RDoc exploite les commentaires placés avant chaque classe et chaque méthode pour générer automatiquement une documentation HTML navigable : titre, auteur, description des paramètres, exemples, lien vers le code source.

# = Script de fonctions mathématiques simples
#
# Ce programme fournit des méthodes pour le calcul de factorielles,
# de sommes d'entiers et de combinaisons.
#
# Auteur:: Pierre Jacoboni
# Version:: 1.0

# Calcule la factorielle d'un entier positif ou nul ($n!$).
#
# [n] Entier naturel positif ou nul (Integer).
#
# Retourne le résultat du calcul sous forme d'un grand entier (+Integer+).
# Lève une +ArgumentError+ si +n+ est négatif.
#
# === Exemple
#
#   facto(0) # => 1
#   facto(5) # => 120
#
def facto(n)
  raise ArgumentError, "n doit être positif ou nul" if n < 0
  res = 1
  for i in 2..n
    res *= i
  end
  res
end

# Calcule la somme des entiers de 1 à +n+ ($1 + 2 + \dots + n$).
#
# [n] Borne supérieure (Integer positif).
#
# Retourne la somme calculée.
#
# === Exemple
#
#   somme(10) # => 55
#
def somme(n)
  (1..n).sum
end

# Calcule le nombre de combinaisons de +k+ éléments parmi +n+ ($C_n^k$).
#
# Cette méthode réutilise #facto.
#
# [n] Nombre total d'éléments (Integer).
# [k] Nombre d'éléments choisis (Integer).
#
# Retourne le coefficient binomial.
# Lève une +ArgumentError+ si +k+ n'est pas dans l'intervalle [0, n].
#
# === Exemple
#
#   combinaison(5, 2) # => 10
#
def combinaison(n, k)
  raise ArgumentError, "k doit être compris entre 0 et n" unless (0..n).include?(k)
  facto(n) / (facto(k) * facto(n - k))
end

# Programme principal (exécuté si lancé en ligne de commande)
if __FILE__ == $PROGRAM_NAME
  val = (ARGV[0] || 5).to_i
  puts "Factorielle de #{val} : #{facto(val)}"
  puts "Somme jusqu'à #{val} : #{somme(val)}"
end

La commande rdoc fonctions_math.rb produit la documentation HTML dans le répertoire doc/. On notera que la méthode facto est ici itérative, ce qui la met à l'abri du problème de pile évoqué plus haut.

$ ruby fonctions_math.rb

Complément Le balisage RDoc et les nouveautés du programme

Les commentaires de fonctions_math.rb utilisent le balisage de RDoc :

  • = Titre et === Sous-titre : titres de niveau 1 et 3 ;
  • +code+ : texte en police de code ; *gras* et _italique_ existent aussi ;
  • [n] description et Auteur:: valeur : listes à étiquettes, pour décrire les paramètres ou les informations du fichier ;
  • une ligne indentée : exemple de code, recopié tel quel ;
  • #facto : lien vers la méthode facto. Les $…$ ne sont pas interprétés : ils s'affichent tels quels.

Le programme emploie aussi des constructions présentées plus loin :

  • raise ArgumentError, "…" if n < 0 lève une exception, sous la forme « modificatrice » du if (section 8.4) ;
  • for i in 2..n parcourt l'intervalle de 2 à n inclus (section 8.5) ;
  • ARGV est le tableau des arguments de la ligne de commande, et ARGV[0] || 5 vaut le premier argument s'il existe, 5 sinon ;
  • if __FILE__ == $PROGRAM_NAME n'est vrai que si le fichier est lancé directement (ruby fonctions_math.rb). Quand un autre programme le charge avec load ou require pour utiliser ses méthodes, le programme principal n'est pas exécuté.

Objets, classes et messages p. 10–15

Ruby applique à la lettre les principes de la programmation objet vus au cours 1. Cette partie les énonce, puis décrit l'opération de base du langage : la transmission d'un message à un objet.

Caractéristiques de Ruby p. 10

Principes Ruby et la programmation objet

  • Toutes les entités manipulées sont des objets.
  • Tout objet est instance d'une classe.
  • Toutes les classes sont des objets.
  • Un objet n'est accessible que par envoi de message.
  • Toutes les procédures sont des méthodes.

Ajout On le vérifie en envoyant le message class : 3.class répond Integer, true.class répond TrueClass, nil.class répond NilClass, et Integer.class répond Class : la classe Integer est elle-même un objet, instance de Class.

Classes, instances et interface p. 10

Définition Classe

Tout objet est instance d'une classe. La classe spécifie la structure et le comportement de ses objets :

  • le nom des variables d'état, ou champs : en Ruby et en Smalltalk, les variables d'instance ;
  • le texte des procédures qui définissent le comportement : les méthodes.

L'objet est responsable des valeurs de ses variables d'état. De l'extérieur, on n'accède à son état que par un envoi de message, c'est-à-dire uniquement si l'objet autorise cet accès.

Définition Interface

L'interface d'un objet est l'ensemble des messages qu'il sait traiter : on ne peut communiquer avec lui qu'au travers des services qu'il offre.

En Ruby, cela se traduit ainsi :

  • l'interface d'un objet est donnée par (un sous-ensemble des) méthodes définies dans sa classe ;
  • les variables d'instance ne peuvent être manipulées de l'extérieur que par des messages adressés à l'objet ;
  • les données propres à un objet ne sont manipulées que par l'objet lui-même : l'unité d'encapsulation est l'objet ;
  • les opérations sur un objet ne dépendent pas des choix de réalisation, mais de son interface.

Transmission de message p. 11

Définition Message, receveur, sélecteur

L'opération de base en Ruby est la transmission d'un message à un objet, appelé le receveur (receiver) du message. Un message est formé d'un sélecteur, le nom de la méthode demandée, et d'éventuels arguments. On l'écrit receveur.sélecteur(arguments).

Interprétation d'un message p. 12

Reprenons la classe Compte et deux de ses instances : unCompte (numéro 8765, solde 5000, titulaire Després) et unAutreCompte (numéro 2345, solde 3 milliards, titulaire Jacoboni).

def depose(uneSomme)
  @solde += uneSomme
end
unCompte.depose(2000)

La méthode depose est exécutée dans le contexte de l'objet unCompte, receveur du message. Le paramètre formel uneSomme est lié à la valeur 2000. La variable @solde désigne le champ solde de l'objet unCompte, c'est-à-dire la variable d'instance du receveur. Le solde de unAutreCompte n'est pas touché.

Mécanisme général Interprétation d'un message

  1. Un message est envoyé à un objet ; il fournit le nom de la méthode à exécuter.
  2. Le corps de la méthode est recherché dans le catalogue des méthodes de la classe du receveur.
  3. Ce corps est exécuté dans l'environnement du receveur : chaque nom de variable d'instance désigne le champ correspondant de l'objet qui a reçu le message.
  4. Le résultat est retourné à l'expéditeur du message.

Complément self, le receveur courant

Pendant l'exécution d'une méthode, le mot-clé self désigne le receveur du message, ici unCompte. @solde est donc le champ solde de self. Un message écrit sans receveur, comme donneTonSolde() à l'intérieur d'une autre méthode de Compte, est envoyé à self. On retrouve self à la section 4.8, pour ajouter une méthode à la classe Integer.

Résultat d'un appel de méthode p. 12–13

Le mot-clé return termine la méthode et retourne la valeur de l'expression qui le suit.

def donneTonSolde()
  return @solde
end

Important Valeur de retour implicite

En l'absence de return, une méthode Ruby retourne le résultat de la dernière expression évaluée.

Dans l'exemple suivant, aucune des deux méthodes n'utilise return.

  # @titulaire  => le titulaire du compte
  # @numero     => le numéro du compte

  def depose(uneSomme)
    @solde += uneSomme
  end

  def initialiseToi(unNombre, unNom, uneSomme)
    @numero, @titulaire, @solde = unNombre, unNom, uneSomme
  end
end

print x.depose(2000), "\n"

initialiseToi retourne la valeur de son affectation multiple, c'est-à-dire le tableau des trois valeurs affectées ; depose retourne le nouveau solde. Ajout @solde += uneSomme est une abréviation de @solde = @solde + uneSomme, et une affectation a pour valeur la valeur affectée.

Ouverture des classes p. 14–15

Pourquoi 1234.reverse échoue-t-il ? Parce que 1234 est une instance de Integer, et que reverse est une méthode de String, pas de Integer. La recherche de la méthode dans la classe du receveur (étape 2 du mécanisme) échoue.

$ ruby Reverse.rb
Reverse.rb:14:in `<main>': undefined method `reverse' for 1234:Integer (NoMethodError)

Ajout Ruby 3.4 formule le même message ainsi : undefined method 'reverse' for an instance of Integer (NoMethodError).

Ruby permet toutefois de rouvrir une classe existante, y compris une classe de base, pour lui ajouter des méthodes.

class Integer
  # Il suffit d'ajouter la méthode à la classe
  def reverse
    return self.to_s.reverse.to_i
  end
end

puts 1234.class     # => Integer
puts 1234.reverse   # => 4321

Ajout Dans la méthode, self est l'entier receveur : il est converti en chaîne, la chaîne est inversée, puis reconvertie en entier. Chaque étape est un message envoyé au résultat de la précédente. Conséquence : 1200.reverse vaut 21, car les zéros de tête disparaissent à la conversion, et (-45).reverse vaut 54, car "54-".to_i s'arrête au signe.

Attention Modifier une classe de base

Cette souplesse est à manier avec prudence : rien n'empêche de redéfinir le comportement des classes de base, y compris les opérateurs les plus élémentaires. Modifier une classe de base affecte tout le programme.

class Integer
  def +(unNombre)
    self - unNombre
  end
end

print "1+1 = "
puts 1+1   # => 0

Variables locales p. 16

Les variables locales ne sont pas initialisées : la première affectation joue le rôle d'une déclaration. Une référence à une variable locale jamais affectée est interprétée comme une tentative d'appel d'une méthode de ce nom, d'où le message d'erreur :

ruby> foo
ERR: (eval):1: undefined local variable or method `foo' for main(Object)

Ajout Ruby 3.4 écrit : undefined local variable or method 'foo' for main (NameError).

La portée d'une variable locale est, en général, le bloc dans lequel elle apparaît : proc { … }, loop { … }, def … end, class … end, module … end, ou le programme entier si aucun de ces cas ne s'applique.

class Compte

  # @titulaire  => le titulaire du compte
  # @numero     => le numéro du compte

  def solde

  end

Complément Appeler un modificateur, méthodes destructives

Le cours ne montre pas l'appel de solde=. Ruby accepte d'écrire monCompte.solde = 500 : c'est un sucre syntaxique pour monCompte.solde=(500), un envoi de message, et non une affectation de variable.

Piège classique : à l'intérieur d'une méthode de Compte, écrire solde = 0 crée une variable locale solde et ne touche pas au compte. Il faut écrire self.solde = 0 pour envoyer le message, ou @solde = 0 pour affecter directement la variable d'instance.

Pour ! : si s = "Bonjour", s.upcase retourne une nouvelle chaîne "BONJOUR" et laisse s intact, alors que s.upcase! modifie s lui-même. Une méthode en ! retourne nil quand elle n'a rien changé : "ABC".upcase! vaut nil.

Affectation et typage dynamique p. 18–19

On affecte un objet comme valeur d'une variable avec le symbole =. L'affectation n'est pas un envoi de message : elle associe à un nom de variable une valeur, c'est-à-dire un objet.

Définition Typage dynamique

Les variables Ruby ne sont pas typées : c'est le typage dynamique. N'importe quel objet peut être affecté à n'importe quelle variable, à tout moment : x = 12, puis x = 12.32, puis x = "titi".

L'exemple suivant utilise un dictionnaire, instance de la classe Hash, qui associe des valeurs à des clés : h[clé] = valeur ajoute un couple, h[clé] retrouve la valeur.

h = Hash.new()           # => {}        instance de Hash créée par new et affectée à h
h.length                 # => 0
h['chien'] = "canine"    # => "canine"  ajout d'un couple clé => valeur
h['vache'] = 'bovine'    # => "bovine"
h[12]      = 'coucou'    # => "coucou"
h['chat']  = 99          # => 99        aucun type imposé, ni aux clés ni aux valeurs
h                        # => {"chien"=>"canine", "vache"=>"bovine", 12=>"coucou", "chat"=>99}
h.class()                # => Hash
h = 12                   # => 12        on peut changer le « type » de h
h.class()                # => Integer

Ajout Depuis Ruby 3.4, un dictionnaire s'affiche avec des espaces autour de la flèche : {"chien" => "canine", "vache" => "bovine", 12 => "coucou", "chat" => 99}.

Pour vérifier l'état d'un objet, on lui envoie le message inspect, qui décrit sa classe et ses variables d'instance.

x = Compte.new()
print x.inspect()
# => #<Compte:0x9db290 @solde=nil, @titulaire=nil, @numero=nil>

x.initialiseToi(12, "Pierre", 32)
print x.inspect()
# => #<Compte:0x9db290 @solde=32, @titulaire="Pierre", @numero=12>

x = Compte.ouvrir(123, "Thierry", 12)
print x.inspect()
# => #<Compte:0x9daac8 @solde=12, @titulaire="Thierry", @numero=123>

À vérifier Ces sorties viennent d'une ancienne version de Ruby. Avec la classe Compte0.rb de la section 4.6 et Ruby 3.4, un objet qui sort de new n'a encore aucune variable d'instance (comme dans vi.rb), et inspect les liste dans l'ordre de leur première affectation. On obtient donc #<Compte:0x…>, puis #<Compte:0x… @numero=12, @titulaire="Pierre", @solde=32>. Les trois nil n'apparaissent que si initialize affecte nil aux trois variables. La méthode ouvrir, elle, est présentée à la partie suivante.

Conseil

La grande majorité des erreurs proviennent d'une initialisation incorrecte. La méthode inspect() permet de vérifier que les objets sont correctement initialisés.

Instanciation et initialisation p. 19–23

Un objet doit être créé, puis ses variables d'instance doivent recevoir des valeurs cohérentes. Ruby sépare ces deux étapes, et laisse au concepteur de la classe le choix de la façon de créer ses objets.

Création d'un objet en deux temps p. 19

  1. Allocation par le système d'une zone mémoire de taille connue : pour un langage non typé, le nombre d'attributs plus un pointeur vers la classe. En Ruby, cette allocation se fait en envoyant un message à la classe de l'objet à créer, c'est-à-dire en exécutant une méthode de classe.
  2. Initialisation des variables d'instance, par des messages adressés à l'objet ; les méthodes d'initialisation doivent être programmées.

Les méthodes new et initialize p. 20–21

Quatre situations montrent comment new et initialize collaborent.

Cas 1 Aucune initialisation prévue

Même sans rien prévoir pour la création et l'initialisation, on peut créer des objets.

class MaClasse
  def disBonjour
    print "Bonjour les gens"
  end
end

x = MaClasse.new()
x.disBonjour()
$ ruby initialisation.rb
Bonjour les gens

Cas 2 Redéfinition de initialize

class MaClasse
  def disBonjour
    print "Bonjour les gens"
  end

  # Méthode d'initialisation, appelée implicitement par new
  def initialize()
    puts "Coucou, je suis la méthode initialize"
  end
end

x = MaClasse.new()
x.disBonjour()
$ ruby initialisation1.rb
Coucou, je suis la méthode initialize
Bonjour les gens

Règles new et initialize

  • La création des instances utilise une méthode de classe : new par défaut, ou une méthode écrite par le concepteur de la classe, qui appellera new.
  • L'initialisation des variables d'instance est réalisée par la méthode initialize, une méthode d'instance privée, appelée automatiquement par new.
  • La méthode initialize doit comporter le même nombre d'arguments que l'appel à new.

Ajout Privée signifie qu'on ne peut pas l'appeler avec un receveur explicite : x.initialize("Autre") lève NoMethodError (private method 'initialize' called for an instance of MaClasse). Seul new l'appelle, sur l'objet qu'il vient d'allouer.

Cas 3 Variable d'instance non initialisée

class MaClasse
  attr_reader :leMonsieur

  def disBonjour()
    print "Bonjour #{@leMonsieur}"
  end
end

x = MaClasse.new()
x.disBonjour()
$ ruby initialisation2.rb
Bonjour

@leMonsieur n'ayant jamais été affectée, elle vaut nil, qui s'affiche comme une chaîne vide.

Cas 4 Initialisation avec paramètre

class MaClasse
  attr_reader :leMonsieur

  def disBonjour()
    print "Bonjour #{@leMonsieur}"
  end

  def initialize(unGars)
    @leMonsieur = unGars
  end
end

x = MaClasse.new("Jacoboni")   # correct
x.disBonjour()                 # => Bonjour Jacoboni

Ajout Ruby 3.4 formule l'erreur ainsi : wrong number of arguments (given 0, expected 1) (ArgumentError).

Règle Paramètres de création

Si la méthode d'initialisation prend des paramètres, ils doivent obligatoirement être fournis lors de la création de l'objet.

Bonne pratique : des méthodes de création « métier » p. 21–22

La méthode new existe toujours implicitement, et l'on pourrait s'en contenter. Mais cela a souvent peu de sens, surtout lorsque des arguments sont nécessaires à la fabrication des objets. La programmation objet étant une activité de simulation, on cherche à se rapprocher du vocabulaire métier pour donner du sens au code : on préfère par exemple créer un compte avec un message ouvrir plutôt qu'avec new.

Algorithme Faut-il définir une méthode de création ?

On se pose deux questions. Q1 : la création demande-t-elle des paramètres ? Q2 : y a-t-il des initialisations à effectuer ?

Démarche selon les réponses à Q1 et Q2
Q1. Paramètres à la création ?Q2. Initialisations à effectuer ?Démarche

  2. Écrire une méthode de classe au nom significatif, avec les paramètres nécessaires, qui se contente d'appeler new avec ces paramètres.

Complément Définir une méthode de classe

Une méthode de classe se définit en préfixant son nom par celui de la classe : def Chanson.creer(…). On rencontre plus souvent def self.creer(…), qui est équivalent : entre class Chanson et end, en dehors de toute méthode, self désigne la classe elle-même.

Après private_class_method :new, new ne peut plus être envoyé avec un receveur explicite. Chanson.new(…) écrit dans le programme principal échoue, mais new(…) écrit sans receveur dans une méthode de classe fonctionne, car le receveur implicite est alors self, la classe.

Exemple complet : statistiques d'un jukebox p. 22–23

Cet exemple combine variable de classe, variables d'instance, méthode de classe de création et méthode d'initialisation.

class Chanson
  @@lecture = 0   # variable de classe : total des lectures
  # Variables d'instance : @nom, @artiste, @duree, @lecture

  # Il y a des paramètres à la création d'une chanson, donc :
  # 1) on n'utilise pas new, et on l'interdit
  private_class_method :new

  # 2) on fournit une méthode de classe pour l'instanciation
  def Chanson.creer(nom, artiste, duree)
    new(nom, artiste, duree)
  end

  # 3) on fournit une méthode d'initialisation
  def initialize(nom, artiste, duree)
    @nom, @artiste, @duree = nom, artiste, duree
    @lecture = 0
  end

  # Méthode d'instance de l'interface : jouer la chanson
  def play()
    @lecture += 1
    @@lecture += 1
    puts "Cette chanson #@nom lecture : #@lecture fois, total des lectures : #@@lecture."
  end
end

s1 = Chanson.creer("Louise", "Fersen", 140)
s2 = Chanson.creer("Dracula", "Fersen", 237)
s1.play() ; s2.play()
s1.play() ; s1.play()
s2.play()
$ ruby Chanson.rb
Cette chanson Louise lecture : 1 fois, total des lectures : 1.
Cette chanson Dracula lecture : 1 fois, total des lectures : 2.
Cette chanson Louise lecture : 2 fois, total des lectures : 3.
Cette chanson Louise lecture : 3 fois, total des lectures : 4.
Cette chanson Dracula lecture : 2 fois, total des lectures : 5.

Ajout @lecture compte les lectures d'une chanson, et chaque chanson a le sien ; @@lecture compte toutes les lectures, et il est partagé par toutes les chansons. Dans une chaîne, #@nom est une abréviation de #{@nom}, valable pour les variables en @, @@ et $. Le point-virgule sépare deux instructions écrites sur la même ligne.

Utiliser Ruby p. 23–25

Solution proposée 
# Classe Compte, épisode 1
class Compte
  # @numero     => le numéro du compte
  # @titulaire  => le nom du titulaire
  # @solde      => le solde du compte

  # Paramètres obligatoires à la création : new est interdit à l'extérieur
  private_class_method :new

  # Méthode de création « métier »
  def Compte.ouvrir(unNumero, unTitulaire, unSolde)
    new(unNumero, unTitulaire, unSolde)
  end

  # Appelée par new, avec les mêmes paramètres
  def initialize(unNumero, unTitulaire, unSolde)
    @numero, @titulaire, @solde = unNumero, unTitulaire, unSolde
  end

  def donneTonSolde()
    return @solde
  end

  def depose(uneSomme)
    @solde += uneSomme
  end

  def retire(uneSomme)
    @solde -= uneSomme
  end

  def afficheToi()
    puts "Compte n° #{@numero} de #{@titulaire} : solde #{@solde}"
  end
end

Bases du langage p. 25–30

Il reste à voir les éléments de base qu'emploie tout programme : les chaînes de caractères, les expressions régulières, les nombres, les conditionnelles et les boucles. En Ruby, ce sont eux aussi des objets et des messages.

Chaînes de caractères p. 25–26

Les chaînes de caractères sont des « conteneurs » homogènes de caractères. Leur manipulation est bien plus intuitive qu'en C : on n'a pas à se soucier de la place occupée ni de la gestion de la mémoire. En C, concaténer deux chaînes impose de gérer explicitement l'allocation.

char *s = malloc(strlen(s1) + strlen(s2) + 1);
strcpy(s, s1);
strcat(s, s2);
/* ... */
free(s);

Guillemets et apostrophes

Une chaîne peut s'écrire entre guillemets ("abc") ou entre apostrophes ('abc'). Les deux formes produisent la même chaîne, mais :

  • entre guillemets, on peut utiliser des séquences d'échappement (une barre oblique inverse devant le caractère voulu, par exemple \n) et évaluer des expressions incluses dans #{…} ;
  • entre apostrophes, rien de tout cela : la chaîne ne dit que ce qu'elle montre.

Exemple La même chaîne, deux délimiteurs Ajout

n = 3
puts "a\tb #{n + 1}"   # affiche a, une tabulation, puis b 4
puts 'a\tb #{n + 1}'   # affiche a\tb #{n + 1}, tel quel

Tests d'égalité

Il faut être attentif à ce que l'on teste.

"foo" == "foo"          # => true   même contenu
"foo".eql?("foo")       # => true   même contenu et même type
"foo".equal?("foo")     # => false  deux objets distincts (identité)

La documentation de Ruby précise la différence entre ==, eql? et equal?. Ajout Sur les nombres, 1 == 1.0 vaut true, mais 1.eql?(1.0) vaut false, car un Integer et un Float ne sont pas du même type. equal? teste l'identité : deux littéraux "foo" créent deux objets différents, de même contenu.

Modification d'une partie de la chaîne

La partie remplacée n'a pas besoin d'avoir la même longueur que le texte de remplacement.

foo[5,1] = "a"     # foo vaut "fishbane"
foo[0,4] = "wolf"  # foo vaut "wolfbane"
foo[1,5] = "i"     # foo vaut "wine"
foo[1,2] = "edg"   # foo vaut "wedge"

Sucre syntaxique [] et []=

Comme tout en Ruby, les chaînes sont des objets : "foofoo".class répond String. Les notations [] et []= sont en réalité des messages envoyés à l'instance de String :

  • foo[2] ⇔ foo.[](2) ;
  • foo[2,1] = "d" ⇔ foo.[]=(2, 1, "d").

Complément Chaînes littérales et Ruby 3.4 Hors programme

Les futures versions de Ruby rendront non modifiables les chaînes écrites littéralement dans le programme. Ruby 3.4 exécute encore foo[0,1] = "f" normalement, mais avec les avertissements activés il signale literal string will be frozen in the future. Pour obtenir à coup sûr une chaîne modifiable, on écrit foo = String.new("wishbone") ou foo = "wishbone".dup.

Expressions régulières p. 27–28

Les expressions régulières (regular expressions) décrivent des motifs de chaînes à l'aide d'un vocabulaire spécialisé. En Ruby, comme en Perl, elles sont délimitées par des barres obliques : /…/. D'abord déroutantes, elles offrent un pouvoir d'expression très concis, qui évite de nombreuses lignes de code pour la reconnaissance de motifs, la recherche et la manipulation de chaînes.

Exemple Un motif en une ligne

Tester si une chaîne « commence par un f minuscule, suivi immédiatement d'exactement une majuscule, suivie de n'importe quoi sauf des minuscules » demanderait une douzaine de lignes en C. Avec une expression régulière :

/^f[A-Z][^a-z]*$/

Ajout "fB12-" correspond au motif ; "fBa" non (une minuscule après la majuscule) ; "FB" non plus (le f est majuscule).

Le programme suivant ajoute deux méthodes à la classe String, en rouvrant la classe comme à la section 4.8, pour savoir si une chaîne représente un entier ou un réel.

class String
  def isEntier?()
    if self =~ /^[+-]?\d+$/
      puts "#{self} est un entier"
    else
      puts "#{self} n'est pas un entier"
    end
  end

  def isReel?()
    if self =~ /^-?\d+(\.\d*)?$/
      puts "#{self} est un réel"
    else
      puts "#{self} n'est pas un réel"
    end
  end
end

"abcd".isReel?()
"12".isReel?()

Complément Lire et améliorer isInteger.rb

  • chaîne =~ /motif/ retourne la position de la première correspondance, ou nil s'il n'y en a pas. Comme nil est faux et un entier vrai (section 8.4), le résultat s'utilise directement comme condition. Après une correspondance, $~, $&, $1, $2… en décrivent le détail (section 5.6).
  • \. désigne un vrai point : seul, . désigne n'importe quel caractère. (\.\d*)? rend facultative la partie décimale.
  • En Ruby, ^ et $ marquent le début et la fin d'une ligne, pas de la chaîne. Une chaîne de deux lignes, "12\nabc", est donc déclarée entière, car sa première ligne l'est. Pour ancrer sur toute la chaîne, on utilise \A et \z.
  • Ces deux méthodes affichent un texte et retournent nil : ce ne sont pas de vrais prédicats, malgré leur ? (section 5.4). Une version conforme à la convention retourne un booléen :
class String
  def entier?
    match?(/\A[+-]?\d+\z/)
  end
end

"12".entier?        # => true
"12.4".entier?      # => false
"12\nabc".entier?   # => false

Complément === selon le receveur

C'est la valeur écrite après when qui reçoit le message ===, avec la valeur testée en argument. Chaque classe lui donne son sens :

(1..5) === 3        # => true   Range : appartenance à l'intervalle
/ab/ === "cabane"   # => true   Regexp : correspondance du motif
Integer === 3       # => true   classe : 3 est-il une instance de Integer ?
String === 3        # => false
3 === 3             # => true   valeur simple : égalité

On peut donc écrire when String pour traiter à part les chaînes, ou when /^h/ pour les chaînes qui commencent par h.

Itérations p. 30

Ruby propose les formes classiques de répétition while et until. Il existe aussi une autre manière, plus idiomatique, de réaliser des itérations : les itérateurs sur les collections, présentés dans le cours 4.

while

while expr [do]
  ...
end

expr while expr

Exécute le corps tant que la condition est vraie. La forme modificatrice répète l'évaluation de l'expression de gauche tant que celle de droite est vraie.

until

until expr [do]
  ...
end

expr until expr

Exécute le corps jusqu'à ce que la condition soit vraie. La forme modificatrice répète l'évaluation de l'expression de gauche jusqu'à ce que celle de droite soit vraie.

Exemple Les deux boucles et la forme modificatrice Ajout

i = 1
while i <= 3
  print i, " "       # affiche 1 2 3
  i += 1
end

until i == 0
  print i, " "       # affiche 4 3 2 1
  i -= 1
end

n = 1
n *= 2 while n < 100 # n vaut 128

for k in 2..4        # boucle for sur un intervalle, comme dans facto
  print k            # affiche 234
end

Ruby n'a pas de boucle for (i = 0; i < n; i++) à la C. Le for … in de fonctions_math.rb parcourt un intervalle ; il repose en réalité sur l'itérateur each du cours 4.

À retenir

L'essentiel

  • Les trois principes de base de Ruby : tout est objet ; tout objet est instance d'une classe ; programmer, c'est envoyer des messages à des objets. Les classes elles-mêmes sont des objets.
  • Un message est formé d'un sélecteur et d'arguments. Il retourne toujours un objet et s'exécute dans le contexte du receveur : sa méthode est cherchée dans la classe du receveur, et @x y désigne le champ du receveur.
  • Sans return, une méthode retourne le résultat de la dernière expression évaluée.
  • Les opérateurs (+, ==, [], []=) sont des messages : 21 + 3 est 21.+(3). Une classe, même de base, peut être rouverte pour ajouter ou redéfinir des méthodes, avec prudence.
  • Variables : locale (nom), d'instance (@nom), de classe (@@nom), globale ($nom), constante (Nom). Rien n'est déclaré, et le typage est dynamique.
  • Les accesseurs se génèrent avec attr_reader, attr_writer et attr_accessor ; pour @solde, ils s'appellent solde et solde=.
  • Conventions : prédicat en ?, méthode destructive en !, variables d'instance décrites en commentaire en tête de classe (exigé dans le module).
  • new alloue l'objet puis appelle initialize, méthode privée, avec les mêmes arguments. Avec des paramètres de création : private_class_method :new et une méthode de classe au nom métier (ouvrir, creer).
  • Chaînes : "…" interprète \n et #{…}, '…' non. == compare le contenu, equal? l'identité.
  • Seuls false et nil sont faux. if, unless et case sont des expressions ; case compare avec ===.

Auto-évaluation

Dans "toto".size, quels sont le receveur, le sélecteur et le résultat ?

Le receveur est la chaîne "toto", instance de String ; le sélecteur est size, sans argument (message unaire). Le résultat est l'objet 4, instance de Integer.

Avec def depose(s) @solde += s end et un compte dont le solde vaut 5000, que retourne unCompte.depose(2000) ?

7000. Il n'y a pas de return : la méthode retourne la valeur de la dernière expression, l'affectation @solde += s, qui vaut la nouvelle valeur de @solde, celle de unCompte.

Pourquoi 1234.reverse lève-t-il NoMethodError, et comment le faire fonctionner ?

1234 est un Integer, et reverse n'est pas dans le catalogue des méthodes de Integer, seulement dans celui de String. On peut rouvrir Integer et y définir reverse, par exemple self.to_s.reverse.to_i.

Que désignent @solde, solde et solde= ? Et que fait solde = 0 écrit dans une méthode de Compte ?

La variable d'instance, la méthode de consultation et la méthode de modification. solde = 0 crée une variable locale solde et ne modifie pas le compte : il faut self.solde = 0 ou @solde = 0.

Que valent "foo" == "foo", "foo".eql?("foo") et "foo".equal?("foo") ?

true, true, false. Les deux premiers comparent le contenu (et le type pour eql?) ; equal? compare l'identité, et les deux littéraux sont deux objets distincts.

Compte.new lève ArgumentError: wrong number of arguments (given 0, expected 3). Pourquoi ? Et quelle démarche adopter pour cette classe ?

new transmet ses arguments à initialize, qui en attend 3 : ils doivent être fournis à la création. Puisqu'il y a des paramètres de création et des initialisations, on interdit new (private_class_method :new), on écrit une méthode de classe métier comme Compte.ouvrir(numero, titulaire, solde) qui appelle new, et initialize prend les mêmes 3 paramètres.

Que vaut @@lecture après trois appels à play sur s1 et deux sur s2 ? Et le @lecture de s1 ?

@@lecture vaut 5 : c'est une variable de classe, partagée par toutes les chansons. Le @lecture de s1 vaut 3 : c'est une variable d'instance, propre à s1.

Qu'affiche puts(if 0 then "vrai" else "faux" end) ? Et pourquoi le C affiche-t-il un 21! négatif ?

vrai : en Ruby, seuls false et nil sont faux. En C (comme en Java), 21! dépasse la capacité d'un long de 64 bits (\(2^{63} - 1 \approx 9{,}22 \times 10^{18}\)) : seuls les 64 bits de poids faible sont gardés, lus comme un nombre négatif, sans aucun message d'erreur.
