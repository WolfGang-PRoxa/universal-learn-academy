Sujet 3 : Spécification et Diagramme de Classes du Jeu de l'Oie

Ce document répond aux questions de modélisation et de conception orientée objet du Sujet 3 (Jeu de l'Oie).

1. Spécification des classes (Réification du domaine)

La phase de réification consiste à modéliser les entités du domaine sous la forme de classes informatiques avec leurs responsabilités, leurs attributs (« ce qu'elles connaissent ») et leurs méthodes (« ce qu'elles savent faire »).

1.1 Classe Jeu

  • Responsabilités :
    • Orchestrer le déroulement global de la partie (gestion des tours de jeu, fin de partie).
    • Maintenir la liste des joueurs participants et la topologie du plateau (point d'entrée vers la première case).
    • Déclarer le vainqueur ou l'élimination de tous les joueurs.
  • Ce qu'elle connaît :
    • @caseDepart : Référence vers la première case du plateau (CaseDepart).
    • @listeDeJoueurs : Collection ordonnée des joueurs encore en jeu.
    • @leJoueurGagnant : Référence vers le joueur ayant atteint la case finale (Joueur, initialement nil).
  • Ce qu'elle sait faire :
    • initialize() : Construit le plateau, initialise la chaîne des cases et inscrit les joueurs.
    • lanceToi() : Lance la boucle principale du jeu tour par tour jusqu'à la victoire ou l'élimination de tous les joueurs.
    • to_s() : Fournit une description textuelle de l'ensemble du plateau.
    • ajouteCase(uneCase) (privée) : Insère une nouvelle case à la fin de la chaîne de cases (mise à jour des liens précédent/suivant).
    • initialiseToi(listeCase, listeJoueur) (privée) : Connecte l'ensemble des cases et enregistre les joueurs.

1.2 Classe Joueur

  • Responsabilités :
    • Représenter un participant au jeu, son identité, son état courant et sa position sur le plateau.
    • Lancer les dés et déclencher son déplacement.
  • Ce qu'elle connaît :
    • @couleur : Nom ou couleur distinctive du joueur (String).
    • @case : Référence vers la case actuelle sur laquelle se trouve le joueur (Case).
    • @statut : État courant du joueur (:enjeu, :elimine, :gagnant).
  • Ce qu'elle sait faire :
    • initialize(uneCouleur, unePosition) : Positionne le joueur sur une case initiale avec le statut :enjeu.
    • joue() : Lance le tour du joueur s'il est toujours en jeu, en tirant les dés et en demandant à sa case actuelle de le faire avancer.
    • tireLesDes() : Génère un résultat aléatoire simulant le jet de dés.
    • estElimine?() : Indique si le joueur a été éliminé de la partie.
    • to_s() : Retourne la description de la position courante du joueur.

1.3 Hiérarchie des Cases (Case et spécialisations)

Le plateau est modélisé par une liste doublement chaînée où chaque case est un maillon capable de propager le déplacement de manière récursive.

A. Classe Case (Comportement de base / Case Neutre)

  • Responsabilités :
    • Servir de brique de base pour le plateau et implémenter le comportement par défaut (case neutre : aucun effet secondaire).
    • Gérer le chaînage bidirectionnel avec les cases voisines.
    • Propager récursivement l'avancement et le recul d'un joueur case par case.
  • Ce qu'elle connaît :
    • @nom : Nom ou intitulé descriptif de la case (String).
    • @caseSuivante : Référence vers la case suivante (Case).
    • @casePrecedente : Référence vers la case précédente (Case).
  • Ce qu'elle sait faire :
    • initialize(unNom) : Initialise le nom de la case.
    • faitAvancer(unJoueur, nCases) : Déplace récursivement le joueur vers la case suivante jusqu'à épuisement du nombre de cases, puis déclenche traite.
    • faitReculer(unJoueur, nCases) : Déplace récursivement le joueur vers la case précédente jusqu'à épuisement du nombre de cases, puis déclenche traite.
    • traite(unJoueur) : Action effectuée lorsque le joueur termine son mouvement sur cette case (affiche la position du joueur ; ne modifie rien pour une case neutre).
    • afficheTout() : Parcourt récursivement la liste pour afficher l'ensemble des cases du parcours.
    • to_s() : Affiche le nom de la case.

B. Classe CaseDepart (Spécialisation de Case)

  • Responsabilités :
    • Servir de butoir au début du jeu.
  • Ce qu'elle connaît :
    • Hérite des attributs de Case.
  • Ce qu'elle sait faire :
    • faitReculer(unJoueur, nCases) : Intercepte et bloque tout recul supplémentaire. Le joueur reste sur la case départ.

C. Classe CaseArrivee (Spécialisation de Case)

  • Responsabilités :
    • Détecter la victoire d'un joueur et gérer le rebond en arrière si le lancer de dés dépasse le nombre de cases restantes.
    • Notifier le jeu de la victoire.
  • Ce qu'elle connaît :
    • @leJeu : Référence vers l'instance de Jeu en cours.
  • Ce qu'elle sait faire :
    • faitAvancer(unJoueur, nCases) : Surcharge l'avancement. Si nCases > 0, fait rebondir le joueur en arrière via self.faitReculer(unJoueur, nCases). Si nCases == 0, le joueur atteint exactement l'arrivée.
    • traite(unJoueur) : Attribue le statut :gagnant au joueur et met à jour leJoueurGagnant du jeu.

D. Classe CasePerdu (Spécialisation de Case)

  • Responsabilités :
    • Éliminer le joueur qui atterrit sur cette case.
  • Ce qu'elle connaît :
    • Hérite des attributs de Case.
  • Ce qu'elle sait faire :
    • traite(unJoueur) : Modifie le statut du joueur à :elimine.

E. Classe abstraite CaseDeplacer (Spécialisation de Case)

  • Responsabilités :
    • Modéliser une case provoquant un déplacement forcé relatif (avancer ou reculer d'un nombre donné de cases).
  • Ce qu'elle connaît :
    • @nbDeCases : Nombre entier de cases du déplacement imposé (Integer).
  • Ce qu'elle sait faire :
    • initialize(unNom, unEntier) : Initialise le nom et l'amplitude du déplacement.

F. Classe CaseAvancer (Spécialisation de CaseDeplacer)

  • Responsabilités :
    • Forcer le joueur à avancer immédiatement de @nbDeCases.
  • Ce qu'elle sait faire :
    • traite(unJoueur) : Fait avancer le joueur de @nbDeCases supplémentaires.

G. Classe CaseReculer (Spécialisation de CaseDeplacer)

  • Responsabilités :
    • Forcer le joueur à reculer immédiatement de @nbDeCases.
  • Ce qu'elle sait faire :
    • traite(unJoueur) : Fait reculer le joueur de @nbDeCases.

H. Classe CaseAllerA (Spécialisation de Case)

  • Responsabilités :
    • Téléporter directement le joueur sur une case cible désignée.
  • Ce qu'elle connaît :
    • @enCase : Référence vers la case de destination (Case).
  • Ce qu'elle sait faire :
    • initialize(unNom, uneCase) : Définit le nom et la case destination.
    • traite(unJoueur) : Déplace le joueur sur @enCase et déclenche le traitement de cette dernière.

3. Analyse des mécanismes de conception

3.1 Chaîne doublement chaînée et récursion

Le plateau n'est pas un simple tableau indexé, mais une liste doublement chaînée (caseSuivante et casePrecedente). Le déplacement s'effectue par récursion terminale : - faitAvancer(joueur, n) déplace le joueur sur self, puis délègue à @caseSuivante.faitAvancer(joueur, n - 1). - Quand n == 0, le joueur s'arrête et la case appelle self.traite(joueur).

3.2 Gestion du rebond à l'arrivée (Élégance du polymorphisme)

Dans CaseArrivee, la méthode faitAvancer est surchargée : ruby def faitAvancer(unJoueur, nCases) unJoueur.case = self self.faitReculer(unJoueur, nCases) return self end - Si le joueur arrive pile avec nCases == 0, faitReculer(..., 0) s'arrête immédiatement et appelle traite(unJoueur), ce qui fait gagner le joueur. - Si nCases > 0, le joueur "dépasse" l'arrivée et rebondit en arrière du nombre exact de pas restants.

3.3 Butoir du départ

Dans CaseDepart, faitReculer est neutralisé : ruby def faitReculer(unJoueur, nCases) unJoueur.case = self return self end Ceci garantit la règle : "Lorsqu'on recule et que l'on revient à la case départ, on reste sur cette case jusqu'au tour suivant."
