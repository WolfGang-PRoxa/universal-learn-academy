Codage de source

Une source n'émet pas tous ses symboles avec la même probabilité. En donnant des mots courts aux symboles fréquents et des mots longs aux symboles rares, on s'approche de son entropie : c'est la compression sans perte. Ce cours présente les codes préfixes et leur arbre, les codes de Shannon-Fano et de Huffman, leur place dans la norme JPEG, puis le codage arithmétique, qui code un message entier par un seul nombre.

Le codage de source diapos 2–4

Le cours 1 a montré qu'une source contient souvent moins d'information que ne le laisse croire le nombre de bits qui la représentent. Le codage de source (source coding) exploite cet écart : il retire la redondance, sans rien perdre du message.

Les familles de codes diapo 2

Le support s'ouvre sur une classification des codes détecteurs et correcteurs d'erreurs.

Complément Lire cette classification

Ces codes relèvent du codage de canal : ils ajoutent une redondance contrôlée pour détecter ou corriger les erreurs de transmission, là où le codage de source en retire. Ils sont l'objet des cours suivants. Le vocabulaire de l'arbre :

  • un code en blocs découpe le message en blocs de \(k\) bits et code chacun indépendamment en \(n\) bits ; un code convolutionnel a une mémoire : chaque sortie dépend aussi des bits précédents ;
  • un code est séparable (on dit aussi systématique) quand les bits d'information apparaissent tels quels dans le mot code, suivis des bits de contrôle ;
  • un code est linéaire quand la somme bit à bit (ou exclusif) de deux mots code est encore un mot code ; il est cyclique quand, de plus, toute permutation circulaire d'un mot code est un mot code.

Retirer la redondance diapo 3

Rappel Entropie relative et redondance diapo 3

Soit \(U\) une source discrète à \(N\) valeurs possibles et d'entropie \(H_\infty(U) \lt \log_2 N\). L'entropie relative \(H_r(U) = \dfrac{H_\infty(U)}{\log_2 N}\) étant strictement plus petite que 1, la redondance \(r = 1 - H_r(U)\) est différente de zéro.

L'élimination de la partie redondante de l'information délivrée par la source peut être obtenue en codant les différentes configurations émises par la source.

Complément Ce que mesure \(H_\infty\)

\(H_\infty(U)\) est l'entropie par symbole quand on tient compte de toutes les dépendances entre symboles successifs : c'est la limite des entropies \(H_n\) de l'expérience de Shannon. Pour une source sans mémoire, dont les symboles sont indépendants, elle se réduit à \(H(U) = -\sum p_i \log_2 p_i\).

Exemple, repris tout au long du cours : une source émet A, B, C, D, E avec les probabilités \(15/39\), \(7/39\), \(6/39\), \(6/39\), \(5/39\). Son entropie vaut \(H \approx 2{,}186\) bits par symbole, pour un maximum de \(\log_2 5 \approx 2{,}322\) : entropie relative ≈ 94,1 %, redondance ≈ 5,9 %. Un code à longueur fixe demande pourtant 3 bits par symbole, car \(2^2 = 4 \lt 5\). Les codes de ce chapitre cherchent à ramener ces 3 bits vers 2,186.

Longueur fixe ou longueur variable diapo 4

Définition Code à longueur fixe, code à longueur variable

Dans un code à longueur fixe (fixed-length code), tous les mots ont la même longueur : ils contiennent le même nombre de symboles.

Dans un code à longueur variable (variable-length code), la longueur des mots varie en fonction de leur fréquence d'apparition : un mot sera d'autant plus long que sa probabilité d'apparition est petite.

Complément Quelle longueur pour un symbole ?

Le code ASCII, qui code chaque caractère sur 7 bits, est à longueur fixe ; le code Morse, vu plus bas, est à longueur variable. Le cours 1 a défini l'incertitude d'un symbole de probabilité \(p\) : \(-\log_2 p\). C'est la longueur idéale de son mot. Dans l'exemple, A (\(p = 15/39\)) mériterait \(1{,}38\) bit et E (\(p = 5/39\)) \(2{,}96\) bits. Une longueur étant entière, aucun code symbole par symbole n'atteint exactement ces valeurs ; on verra que le codage arithmétique contourne cette limite.

Généralités sur les codes diapos 5–8

Avec des mots de longueurs différentes, une difficulté apparaît : le récepteur reçoit une suite de bits sans séparateur, et doit retrouver seul où finit chaque mot.

Définition Alphabet, mot, code diapo 5

Soit \(B\) un alphabet de référence, c'est-à-dire un ensemble de lettres (en général, \(B\) est l'alphabet binaire \(B = \{0, 1\}\)). En concaténant des lettres de l'alphabet \(B\), on forme des mots dont la longueur correspond au nombre de lettres utilisées. Un code \(C\) est un ensemble de mots.

Code uniquement déchiffrable diapo 6

Définition Code uniquement déchiffrable

Un code est uniquement déchiffrable (uniquely decodable) si toute suite de mots code ne peut être interprétée (décodée) que d'une seule manière.

Exemple 1 Un code de longueur fixe diapo 6

Avec \(B = \{0, 1\}\), \(C = \{00, 01, 10, 11\}\) est un code de longueur fixe égale à 2.

Ajout Il est uniquement déchiffrable, comme tout code de longueur fixe à mots distincts : il suffit de couper la suite reçue tous les deux bits. 011100 se lit 01 | 11 | 00, et d'aucune autre façon.

Code préfixe diapo 7

Exemple 2 Déchiffrable ou non diapo 7

Le code \(\{0, 11, 010\}\) est uniquement déchiffrable.

Le code \(\{0, 1, 101\}\), dont on note les mots \(\alpha = 0\), \(\beta = 1\) et \(\gamma = 101\), n'est pas uniquement déchiffrable : la suite 101 peut être interprétée comme \(\beta\alpha\beta\) ou comme \(\gamma\).

Définition Code préfixe diapo 7

Un code préfixe (prefix code) est un code pour lequel aucun mot n'est le début d'un autre mot.

Propriété Un code préfixe est uniquement déchiffrable

Il est clair qu'un code préfixe est uniquement déchiffrable.

Preuve

Ajout On lit les bits un à un jusqu'à reconnaître un mot du code. Aucun mot n'étant le début d'un autre, ce premier mot reconnu est le seul possible : un mot plus long qui commencerait par lui n'existe pas. On l'émet, puis on recommence sur la suite. Chaque découpage est forcé, donc la lecture est unique.

Complément La réciproque est fausse

Le code \(\{0, 11, 010\}\) de l'exemple 2 est uniquement déchiffrable sans être préfixe : 0 est le début de 010. Après un 0, le décodeur ne sait pas encore s'il tient le mot 0 ou le début de 010. Il doit regarder les bits suivants : 011 ne peut être que 0 | 11, et 010 ne peut être que 010, car aucun mot ne commence par 10.

Un code préfixe, lui, se décode au fil de l'eau, sans attendre la suite : on l'appelle aussi code instantané (instantaneous code). C'est pourquoi les codes de ce chapitre sont tous préfixes.

L'arbre d'un code diapo 8

Un code binaire se représente par un arbre. Depuis la racine, on descend à gauche pour un 0 et à droite pour un 1 : chaque mot est le chemin qui mène de la racine à un nœud de l'arbre.

Le code \(\{0, 10, 110, 111\}\) est un code préfixe. Le code \(\{0, 11, 110, 111\}\) n'est pas un code préfixe, car le chemin menant à 11 est inclus dans les chemins menant à 110 et à 111.

Méthode Reconnaître et décoder un code préfixe sur son arbre

Ajout Un code est préfixe si et seulement si tous ses mots sont des feuilles de son arbre : aucun mot n'est alors sur le chemin d'un autre. Pour décoder, on part de la racine et on suit les bits reçus ; à chaque feuille atteinte, on émet son mot et on repart de la racine. Avec \(\{0, 10, 110, 111\}\), la suite 0110100 se lit 0 | 110 | 10 | 0.

Pour aller plus loin : l'inégalité de Kraft Hors programme

Des longueurs \(\ell_1, \dots, \ell_n\) sont celles d'un code préfixe binaire si et seulement si

\[ \sum_{i=1}^{n} 2^{-\ell_i} \le 1. \]

Un mot de longueur \(\ell\) « occupe » la fraction \(2^{-\ell}\) des feuilles d'un arbre complet, et deux mots d'un code préfixe n'occupent jamais les mêmes feuilles. Pour \(\{0, 10, 110, 111\}\) : \(1/2 + 1/4 + 1/8 + 1/8 = 1\), l'arbre est plein. McMillan a montré que la même inégalité vaut pour tout code uniquement déchiffrable : se limiter aux codes préfixes ne fait donc rien perdre.

Complément Lire la colonne Durée

La durée est comptée en unités de temps : un point dure 1 unité, un trait 3 ; chaque signe est suivi d'un silence de 1 unité, et chaque lettre d'un silence supplémentaire de 3 unités. Ainsi E (·) dure \(1 + 1 + 3 = 5\), A (· −) dure \((1 + 1) + (3 + 1) + 3 = 9\) et O (− − −) dure \(3 \times (3 + 1) + 3 = 15\). Cette règle redonne les 26 durées du tableau (vérifié par programme) ; l'espace entre deux mots dure 6 unités.

Complément Pourquoi trois symboles ?

Les lettres fréquentes ont les codes les plus courts (E : 5 unités, T et I : 7) et les lettres rares les plus longs (J, Q, Y : 17). La correspondance n'est pas parfaite : O, assez fréquent (0,0632), dure 15 unités, plus que M (0,0198), qui en dure 11. En pondérant par les fréquences, dont la somme vaut 1 avec l'espace, un caractère dure en moyenne \(\sum p_i\, d_i \approx 9{,}3\) unités.

Surtout, le Morse n'est pas un code préfixe : le code de E (·) est le début de celui de A (· −), celui de T (−) le début de celui de N (− ·). Sans séparation, « · − » se lirait A ou ET. Le silence entre les lettres est donc indispensable : c'est un troisième symbole, et le Morse est un code ternaire.

Le code de Shannon-Fano diapos 10–14

Le premier code construit pour une source donnée part de l'ensemble des symboles et le coupe en deux groupes de probabilités voisines, puis recommence dans chaque groupe. L'arbre se construit donc de haut en bas.

Principe Code de Shannon-Fano diapo 10

Le code de Shannon-Fano (Shannon-Fano coding) est le premier code utilisé pour exploiter la redondance d'une source.

Algorithme Somme de probabilités : étapes diapo 10

  1. Classer les symboles par probabilités décroissantes.
  2. Partager la liste en deux groupes consécutifs dont les sommes de probabilités sont aussi proches que possible.
  3. Attribuer le bit 0 au premier groupe et le bit 1 au second.
  4. Recommencer les étapes 2 et 3 dans chaque groupe qui contient plus d'un symbole.
  5. S'arrêter quand chaque groupe ne contient plus qu'un symbole : le mot code d'un symbole est la suite des bits qu'il a reçus, division après division.

Ajout La diapo 10 numérote cinq étapes, de (1) à (5), mais leur texte n'apparaît pas, ni dans le texte du PDF ni sur l'image de la diapo. Les étapes ci-dessus sont reconstituées : ce sont celles de l'algorithme classique, et elles redonnent exactement le tableau de la diapo 12.

Complément Le choix de chaque division

  • Première division : \(\{A, B\}\) pèse \(22/39\) et \(\{C, D, E\}\) \(17/39\), soit un écart de \(5/39\). Couper après A donnerait \(15/39\) contre \(24/39\) (écart \(9/39\)), et après C \(28/39\) contre \(11/39\) : la coupure après B est la meilleure.
  • Deuxième division : \(\{A, B\}\) se sépare en A et B.
  • Troisième division : \(\{C, D, E\}\) se coupe en \(\{C\}\) (\(6/39\)) et \(\{D, E\}\) (\(11/39\)), écart \(5/39\), plutôt qu'en \(\{C, D\}\) (\(12/39\)) et \(\{E\}\) (\(5/39\)), écart \(7/39\).
  • Quatrième division : \(\{D, E\}\) se sépare en D et E.

Mesure de l'information diapo 14

La longueur moyenne d'un mot code est :

\[ 2 \cdot \tfrac{15}{39} + 2 \cdot \tfrac{7}{39} + 2 \cdot \tfrac{6}{39} + 3 \cdot \tfrac{6}{39} + 3 \cdot \tfrac{5}{39} = 2{,}282 \text{ bits.} \]

Ce nombre est à comparer avec l'entropie de la source :

\[ -\left\{ \tfrac{15}{39} \log_2 \tfrac{15}{39} + \tfrac{7}{39} \log_2 \tfrac{7}{39} + 2 \cdot \tfrac{6}{39} \log_2 \tfrac{6}{39} + \tfrac{5}{39} \log_2 \tfrac{5}{39} \right\} = 2{,}1858 \text{ Sh.} \]

Le code de Shannon-Fano était utilisé dans les télétypes des années cinquante.

Complément Longueur moyenne, shannon, efficacité

La longueur moyenne (average codeword length) d'un code qui attribue un mot de longueur \(\ell_i\) au symbole de probabilité \(p_i\) vaut \(\bar L = \sum_i p_i\, \ell_i\). Elle se mesure en bits, au sens de chiffres binaires. L'entropie se mesure en shannons (Sh) : l'unité de quantité d'information, celle d'un choix entre deux possibilités équiprobables. Les deux se comparent directement.

Le premier théorème de Shannon, ou théorème du codage de source, fixe la limite : pour tout code uniquement déchiffrable, \(\bar L \ge H\), et il existe un code préfixe tel que \(\bar L \lt H + 1\). On mesure donc un code par son efficacité \(\eta = H / \bar L\) :

\[ \bar L = \sum_i p_i\, \ell_i \;\ge\; H \qquad\qquad \eta = \frac{H}{\bar L} \le 1 \]

Ici, \(\eta = 2{,}1858 / 2{,}282\), soit environ 95,8 %, contre \(2{,}1858 / 3\), soit 72,9 %, pour le code à longueur fixe de 3 bits.

Le code de Huffman diapos 15–23

Shannon-Fano doit choisir chaque coupure, et un mauvais premier choix se paie ensuite. Huffman prend le problème dans l'autre sens : il part des symboles les moins probables, ceux qui auront les mots les plus longs, et remonte jusqu'à la racine.

Principe Code de Huffman diapo 15

Dans le code de Huffman (Huffman coding), la construction de l'arbre permettant d'affecter aux \(n\) lettres source un mot code s'effectue de façon ascendante (contrairement au code de Shannon-Fano).

Algorithme Construction de l'arbre : étapes diapos 15–19

  1. Première étape : on classe les lettres source suivant l'ordre croissant de leur probabilité.
  2. Deuxième étape : on crée un nœud parent à partir des deux lettres source de probabilités les plus faibles.
  3. Troisième étape : on affecte au nœud parent une probabilité égale à la somme des probabilités des deux lettres source à l'origine du nœud parent.
  4. Quatrième étape : on élimine de la liste les deux précédentes lettres source et on les remplace par le « super symbole » constitué par le nœud parent.

Considérant les \(n - 1\) lettres source restantes, on revient à la deuxième étape jusqu'à ce qu'il ne reste plus de lettre source. Ajout C'est-à-dire jusqu'à ce que la liste ne contienne plus qu'un nœud, la racine, de probabilité 1. Le mot code d'une lettre se lit ensuite sur le chemin de la racine à sa feuille : 0 pour une branche, 1 pour l'autre.

Exemple diapos 20–21

On reprend l'exemple précédent, constitué des cinq lettres A, B, C, D, E affectées des fréquences relatives d'apparition \(15/39\), \(7/39\), \(6/39\), \(6/39\), \(5/39\).

  1. (I) Les deux plus petites probabilités sont celles de E (\(5/39\)) et de D (\(6/39\)) : leur nœud parent vaut \(11/39\).
  2. (II) Il reste A (\(15/39\)), B (\(7/39\)), C (\(6/39\)) et le nœud \(11/39\) : C et B donnent un nœud de \(13/39\).
  3. (III) Les nœuds \(11/39\) et \(13/39\) donnent un nœud de \(24/39\).
  4. (IV) Ce nœud et A (\(15/39\)) donnent la racine, \(39/39 = 1\).

Remarque Les choix libres

Ajout À l'étape (I), C et D sont à égalité (\(6/39\)) : l'arbre de la diapo associe D à E, mais associer C à E serait tout aussi correct. De même, le bit 0 ou 1 attribué à chaque branche est libre. Ces choix changent les mots, jamais leurs longueurs dans ce cas, ni la longueur moyenne.

Résultats diapo 22

Le code binaire obtenu est : E = 000, D = 001, C = 010, B = 011, A = 1. La longueur moyenne d'un mot s'écrit :

\[ 3 \cdot \left( 1 - \tfrac{15}{39} \right) + 1 \cdot \tfrac{15}{39} = 2{,}23 \text{ bits.} \]

Ajout Exactement \(87/39 \approx 2{,}231\) bits, soit une efficacité de \(2{,}1858 / 2{,}231\), environ 98,0 %.

Shannon-Fano ou Huffman ? diapo 23

  • Un code de Huffman est toujours au moins aussi performant qu'un code de Shannon-Fano.
  • Le codage de Huffman (comme celui de Shannon-Fano) nécessite la connaissance des probabilités a priori des lettres source. En fait, si on ne connaît pas ces nombres, on peut toujours les estimer en mesurant les fréquences d'apparition des différents symboles dans le message à transmettre. Mais il faudra alors transmettre la table des probabilités ainsi estimées pour que le décodage soit possible.

Complément D'où vient le gain de Huffman

A représente plus du tiers des symboles (\(15/39\), environ 38 %). Sa longueur idéale, \(-\log_2 (15/39) \approx 1{,}38\) bit, est plus proche de 1 que de 2. Huffman lui donne 1 bit ; Shannon-Fano, contraint par sa première coupure équilibrée, lui en donne 2.

Plus généralement, dans un code optimal, les deux symboles les moins probables ont les mots les plus longs, et on peut toujours les placer comme deux feuilles sœurs au fond de l'arbre. C'est exactement ce que fait chaque étape de Huffman, ce qui rend son code optimal parmi les codes qui codent les symboles un par un. Il atteint \(\bar L = H\) quand toutes les probabilités sont des puissances de \(1/2\).

Complément Algorithme avec une file de priorité

En pratique, la liste triée de l'étape 1 est une file de priorité : chaque tour en extrait les deux nœuds les moins probables et y remet leur parent. Pour \(n\) symboles, il y a \(n - 1\) tours.

fonction Huffman(symboles, p)
    F ← file de priorité des feuilles s, de clé p(s)    // la plus petite clé sort en premier
    tant que F contient plus d'un nœud faire
        x ← extraire_min(F)
        y ← extraire_min(F)
        z ← nouveau nœud : fils x (branche 0) et y (branche 1), clé p(x) + p(y)
        insérer z dans F
    fin tant que
    retourner extraire_min(F)                       // la racine, de clé 1
// mot de s : bits lus sur le chemin de la racine à la feuille s

Exercice 2 Shannon-Fano contre Huffman

Ajout Une source émet six symboles A, B, C, D, E, F avec les probabilités 0,39 ; 0,18 ; 0,15 ; 0,14 ; 0,11 ; 0,03.

  1. Construire le code de Shannon-Fano de cette source et donner la longueur de chaque mot.
  2. Construire un code de Huffman et donner la longueur de chaque mot.
  3. Calculer les deux longueurs moyennes et l'entropie de la source. Quel code est le plus efficace ?
Indice

Shannon-Fano : la première coupure sépare \(\{A, B\}\) du reste (0,57 contre 0,43). Huffman : on commence par fusionner F (0,03) et E (0,11).

Exercice 3 Décoder un message

Ajout Décoder la suite 1011000110101 avec le code de Huffman du cours (A = 1, B = 011, C = 010, D = 001, E = 000). Combien de bits aurait demandé le code de Shannon-Fano pour le même message ?

Indice

Le code est préfixe : lire les bits de gauche à droite et couper dès qu'un mot est reconnu.

Solution proposée

1 | 011 | 000 | 1 | 1 | 010 | 1, soit le message ABEAACA, codé en 13 bits. Avec Shannon-Fano (A = 00, B = 01, C = 10, E = 111), il faudrait \(2 + 2 + 3 + 2 + 2 + 2 + 2 = 15\) bits : les quatre A coûtent chacun un bit de plus.

Compression d'images : la norme JPEG diapos 24–30

Le codage de Huffman sert rarement seul. Dans la compression d'images, il intervient en dernier, après des transformations qui, elles, acceptent de perdre de l'information.

Le codage de Huffman correspond à une des étapes de la compression des images suivant les normes JPEG (Joint Photographic Experts Group) pour les images fixes, et MPEG (Moving Picture Experts Group) pour les images animées. Le procédé de compression JPEG peut être schématisé comme suit.

La diapo 24 développe MPEG en « Moving Photographic Experts Group » : le nom du groupe de normalisation est « Moving Picture Experts Group ».

Découpage en blocs diapo 26

L'image est représentée par une matrice dont les éléments correspondent aux valeurs prises par les pixels. On la décompose en blocs de \(8 \times 8 = 64\) pixels, de façon à ce que les calculs de DCT puissent être effectués en un laps de temps raisonnable.

La DCT diapo 27

Définition Transformée en cosinus discrète

La DCT (Discrete Cosine Transform, transformée en cosinus discrète) est une opération similaire au calcul de la transformée de Fourier discrète à deux dimensions (variables d'espace). On obtient alors une nouvelle matrice, de mêmes dimensions que la première, où les éléments correspondent à des mots de 11 éléments binaires (les termes de la matrice initiale étaient codés sur 8 éléments binaires).

Complément Ce que fait la DCT

La DCT écrit le bloc comme une somme de 64 motifs en cosinus, de fréquences croissantes. Le coefficient en haut à gauche mesure le niveau moyen du bloc ; les autres décrivent des variations de plus en plus fines, horizontales vers la droite, verticales vers le bas. Sur une photographie, les pixels voisins se ressemblent : l'essentiel de l'énergie se concentre dans les coefficients du coin haut gauche, et ceux du coin bas droit sont petits.

La DCT elle-même ne perd rien : elle est inversible. Elle ne compresse pas non plus, puisqu'elle passe de 8 à 11 bits par terme. Elle prépare le terrain de l'étape suivante.

La formule de la DCT et ses 11 bits Hors programme

Pour un bloc \(f(x, y)\), \(0 \le x, y \le 7\), dont on a retranché 128 à chaque pixel (valeurs entre −128 et 127) :

\[ F(u, v) = \frac14\, C(u)\, C(v) \sum_{x=0}^{7} \sum_{y=0}^{7} f(x, y) \cos\frac{(2x+1)u\pi}{16} \cos\frac{(2y+1)v\pi}{16}, \qquad C(0) = \frac{1}{\sqrt 2},\ C(k) = 1 \text{ sinon.} \]

Pour \(u = v = 0\), les cosinus valent 1 et \(F(0, 0) = \sum f(x, y) / 8\), soit 8 fois la moyenne des 64 pixels. Sa valeur absolue peut atteindre \(8 \times 128 = 1024 = 2^{10}\) : avec le signe, il faut 11 bits, ce qui explique les 11 éléments binaires de la diapo 27.

Quantification : perte d'informations diapo 28

La quantification (quantization) consiste à réduire le nombre d'éléments binaires pour représenter les coefficients de la matrice. Ainsi les termes situés dans la partie haute gauche de la matrice se verront accorder, pour les représenter, un nombre d'éléments binaires plus important que les termes localisés dans la partie basse droite de la matrice.

Complément Quantifier en pratique

Chaque coefficient est divisé par un pas \(Q(u, v)\) puis arrondi : \(F_Q(u, v) = \operatorname{arrondi}\big(F(u, v) / Q(u, v)\big)\). La table des pas est petite en haut à gauche et grande en bas à droite, car l'œil perçoit mal les détails fins. Beaucoup de coefficients de haute fréquence deviennent nuls. C'est la seule étape qui perd de l'information, et le réglage de « qualité » d'un logiciel ne fait que multiplier les pas.

Parcours en zigzag diapo 29

Ensuite, les valeurs de la matrice sont rangées à partir d'une excursion en zigzag effectuée sur la matrice, en débutant par le terme situé en haut à gauche.

Le coefficient DC diapo 30

Chaque bloc de \(8 \times 8\) possède un coefficient noté DC (situé en haut à gauche), correspondant en quelque sorte à la « valeur moyenne » des 63 autres coefficients, notés AC.

Tenant compte du fait qu'il existe généralement une corrélation assez forte entre les coefficients DC de blocs adjacents, on ne code pas la valeur de DC, mais la différence entre le coefficient DC du bloc précédent et celui que l'on vient de lire.

Contrairement à ce que dit la diapo, le coefficient DC n'est pas la moyenne des 63 coefficients AC : il est proportionnel à la moyenne des 64 pixels du bloc (8 fois cette moyenne, voir le dépliant sur la formule). Les coefficients AC décrivent les variations autour de ce niveau moyen. Les noms viennent de l'électricité : DC pour direct current (courant continu, fréquence nulle) et AC pour alternating current (courant alternatif).

Complément Ce que recouvre l'étape « compression »

Le zigzag range les coefficients des basses fréquences vers les hautes : les zéros produits par la quantification se retrouvent groupés en fin de parcours. On code alors les 63 coefficients AC par plages, comme le fax du cours 1 : chaque valeur non nulle est précédée du nombre de zéros qui la précèdent, et un marqueur de fin de bloc (EOB, end of block) remplace tous les zéros restants. Les couples obtenus, et les différences de DC, sont enfin codés par Huffman : c'est là qu'intervient le code de la section précédente.

Exemple : après quantification, un bloc donne DC = 52 (celui du bloc précédent valait 49) puis, dans l'ordre du zigzag, les AC −3, 1, 0, 0, 2, 0, 0, 0, 0, −1 suivis de 53 zéros. On code la différence \(+3\) pour DC, puis les couples (0 zéro, −3), (0, 1), (2, 2), (4, −1) et EOB : cinq symboles au lieu de 63 valeurs.

Le codage arithmétique diapos 31–34

Huffman attribue à chaque symbole un nombre entier de bits, ce qui l'empêche d'atteindre exactement l'entropie. Le codage arithmétique contourne cette limite : il ne code plus les symboles un par un, mais le message entier.

Principe Codage arithmétique diapo 31

Le principe du codage arithmétique (arithmetic coding) consiste à affecter à l'ensemble du message un seul nombre en virgule flottante.

Ajout Si l'intervalle courant est \([b\,;\,b + e[\), d'écart \(e\), et que le symbole suivant \(s\) a pour intervalle \([a_s\,;\,b_s[\) dans le tableau, le nouvel intervalle et le nouvel écart sont :

Attention La précision des calculs

Ajout Onze lettres demandent déjà 21 décimales, et un double n'en garde qu'environ 16 significatives : un codeur écrit naïvement en virgule flottante se trompe dès les messages moyens. Les vrais codeurs calculent sur des entiers et émettent les chiffres dès qu'ils sont fixés. Après « HAN », par exemple, les deux bornes commencent par 0,384 : ces trois chiffres ne changeront plus, on peut les envoyer et agrandir l'intervalle d'un facteur 1000.

Complément Lire le tableau

  • Huffman et le codage arithmétique sont très proches (31,0 % et 31,5 % en moyenne) : avec des probabilités peu déséquilibrées, les longueurs entières de Huffman coûtent peu.
  • Le Huffman adaptatif fait mieux (33,3 %) : l'arbre est mis à jour au fil de la lecture, de la même façon chez le codeur et chez le décodeur. Il suit les variations locales du fichier, et il n'y a plus de table de probabilités à transmettre.

Travail personnel : LZ78 et LZW diapo 36

La dernière diapo fixe un objectif de travail personnel : « Le code de Lempel-Ziv-Welch (LZW) – Algorithme LZ78 ? ». Les blocs qui suivent proposent une réponse ; ils ne viennent pas du support.

Complément Le principe des codes à dictionnaire

Un code à dictionnaire (dictionary coder) ne s'appuie sur aucune probabilité. Il remplace chaque chaîne déjà rencontrée par son numéro dans un dictionnaire, construit au fil de la lecture. Le décodeur reconstruit le même dictionnaire à partir de ce qu'il décode : il n'y a rien d'autre à transmettre que la suite des numéros. C'est la réponse à la limite relevée à la diapo 23.

Ces codes descendent des algorithmes de Lempel et Ziv, LZ77 (1977) et LZ78 (1978). LZW est la variante de LZ78 publiée par Welch en 1984.

Complément LZ78

Le dictionnaire part vide ; l'entrée 0 représente la chaîne vide. À chaque pas, on lit la plus longue chaîne \(w\) déjà présente dans le dictionnaire, puis le caractère \(c\) qui la suit. On émet le couple (numéro de \(w\), \(c\)) et on ajoute \(w + c\) au dictionnaire.

Pour CHACHACHAT : (0, C) (0, H) (0, A) (1, H) (3, C) (2, A) (0, T). Le dictionnaire contient alors 1 = C, 2 = H, 3 = A, 4 = CH, 5 = AC, 6 = HA, 7 = T.

Complément LZW

Welch initialise le dictionnaire avec tous les symboles de l'alphabet (les 256 octets pour un fichier). Toute chaîne d'un caractère est donc connue d'avance, et il suffit d'émettre des numéros, sans caractère à côté. Quand \(w + c\) n'est pas dans le dictionnaire, on émet le numéro de \(w\), on ajoute \(w + c\), et on repart de \(c\).

fonction CoderLZW(texte)
    dictionnaire ← un numéro pour chaque symbole de l'alphabet
    w ← chaîne vide
    pour chaque caractère c de texte faire
        si w + c est dans le dictionnaire alors
            w ← w + c                          // on allonge la chaîne reconnue
        sinon
            émettre numéro(w)
            ajouter w + c au dictionnaire
            w ← c
        fin si
    fin pour
    émettre numéro(w)

Complément Décoder LZW

Le décodeur part du même dictionnaire initial. Il traduit chaque numéro, et crée l'entrée que le codeur avait créée un pas plus tôt : la chaîne précédente suivie de la première lettre de la chaîne courante. Pour 2 3 1 5 7 6 4 : C, puis H (entrée 5 = CH), A (6 = HA), CH (7 = AC), AC (8 = CHA), HA (9 = ACH), T (10 = HAT), soit CHACHACHAT.

Attention Le numéro pas encore connu

Ajout Le décodeur a un pas de retard sur le codeur : il peut recevoir le numéro de l'entrée qu'il est justement en train de créer. Avec A = 1 et B = 2, ABABABA se code 1 2 3 5. Quand le décodeur lit 5, il n'a créé que 3 = AB et 4 = BA. L'entrée 5 commence forcément par la chaîne précédente, AB, et se termine par sa propre première lettre : c'est ABA. Oublier ce cas est l'erreur classique d'un décodeur LZW.

Complément Taille des numéros

Avec des numéros de 12 bits, le dictionnaire compte au plus \(2^{12} = 4096\) entrées ; avec 15 bits, \(2^{15} = 32\,768\). En longueur variable, on commence à 9 bits (256 octets plus quelques entrées) et on passe à 10, 11, puis 12 bits quand le dictionnaire se remplit. Une fois plein, on le fige ou on le vide pour recommencer. LZW a servi dans la commande compress d'Unix et dans les formats GIF et TIFF.

À retenir

L'essentiel

  • Un code à longueur variable donne des mots courts aux symboles fréquents et longs aux symboles rares ; la longueur idéale d'un symbole de probabilité \(p\) est \(-\log_2 p\).
  • Un code est uniquement déchiffrable si toute suite de mots ne se décode que d'une façon ; il est préfixe si aucun mot n'est le début d'un autre. Préfixe implique uniquement déchiffrable, pas l'inverse (\(\{0, 11, 010\}\)).
  • Sur l'arbre d'un code, un code est préfixe quand tous ses mots sont des feuilles ; il se décode alors au fil de l'eau, en repartant de la racine à chaque feuille.
  • Le Morse est à longueur variable mais pas préfixe (E = · débute A = · −) : le silence entre lettres est un troisième symbole, c'est un code ternaire.
  • Longueur moyenne \(\bar L = \sum p_i \ell_i \ge H\) ; efficacité \(H / \bar L\). Pour la source \(15/39\), \(7/39\), \(6/39\), \(6/39\), \(5/39\) : \(H = 2{,}1858\) Sh.
  • Shannon-Fano construit l'arbre de haut en bas, en coupant la liste triée en deux groupes de probabilités voisines : 2,282 bits sur l'exemple.
  • Huffman construit l'arbre de bas en haut, en fusionnant à chaque étape les deux nœuds les moins probables : 2,23 bits sur l'exemple. Il est toujours au moins aussi bon que Shannon-Fano, mais il faut connaître les probabilités ou transmettre leur table.
  • JPEG : blocs 8 × 8, DCT (8 → 11 bits, sans perte), quantification (la seule perte, forte sur les hautes fréquences), zigzag, DC codé par différence, puis plages et Huffman.
  • Codage arithmétique : chaque symbole réduit l'intervalle courant \([b\,;\,b + e[\) à \([b + e\,a_s\,;\,b + e\,b_s[\) ; un nombre du dernier intervalle (sa borne inférieure) code tout le message, en environ \(-\log_2 e\) bits.
  • LZW remplace les chaînes déjà vues par leur numéro dans un dictionnaire que le décodeur reconstruit seul ; il exploite les répétitions et donne les meilleurs taux du tableau (≈ 47 % en moyenne).

Auto-évaluation

Pour la source A, B, C, D, E du cours, pourquoi un code de 3 bits par symbole est-il peu efficace ?

Son entropie vaut 2,186 Sh : 3 bits par symbole donnent une efficacité de 73 % seulement. Il faut 3 bits pour distinguer 5 symboles à longueur fixe, alors que Huffman descend à 2,23 bits en moyenne.

Le code {0, 10, 110, 111} est-il préfixe ? Décoder 1100100.

Oui : ses mots sont les feuilles de son arbre. 110 | 0 | 10 | 0 : 110, 0, 10, 0.

Une source émet A, B, C, D avec les probabilités 1/2, 1/4, 1/8, 1/8. Quel code de Huffman, et quelle efficacité ?

A = 0, B = 10, C = 110, D = 111 (aux choix de 0 et 1 près). \(\bar L = 1/2 + 2/4 + 3/8 + 3/8 = 1{,}75\) bit, égal à l'entropie : efficacité 100 %, car toutes les probabilités sont des puissances de \(1/2\).

Pourquoi Huffman fusionne-t-il toujours les deux nœuds les moins probables ?

Parce que, dans un code optimal, les deux symboles les moins probables ont les mots les plus longs et peuvent être deux feuilles sœurs au fond de l'arbre. En les fusionnant, on fixe leur dernier bit et on se ramène à une source d'un symbole de moins.

Dans la chaîne JPEG, quelle étape perd de l'information ? À quoi sert le zigzag ?

La quantification : la DCT est inversible, et le codage final (plages, Huffman) est sans perte. Le zigzag range les coefficients des basses vers les hautes fréquences, pour grouper en fin de parcours les zéros produits par la quantification et les coder d'un seul symbole.

Avec le tableau d'intervalles de HANS ZIMMER, par quelles deux lettres commence le message codé par 0,6 ?

0,6 est dans \([0{,}46\,;\,0{,}64[\) : M. Puis \((0{,}6 - 0{,}46) / 0{,}18 \approx 0{,}78\), dans \([0{,}73\,;\,0{,}82[\) : R. Le message commence par MR.

En codage arithmétique, que vaut l'écart du dernier intervalle ?

Le produit des probabilités de tous les symboles du message. Il faut environ \(-\log_2\) de cet écart bits pour désigner un nombre de l'intervalle, soit la somme des \(-\log_2 p\) des symboles.

Pourquoi LZW n'a-t-il pas besoin de transmettre son dictionnaire ?

Le dictionnaire initial (l'alphabet) est convenu d'avance, et chaque nouvelle entrée se déduit de ce qui a déjà été décodé : le décodeur reconstruit le même dictionnaire, avec un pas de retard.
