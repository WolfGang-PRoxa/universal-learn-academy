Le langage C notes, début

Avant d'écrire du C, il est utile de savoir d'où vient ce langage et ce qui le distingue : il est ancien, proche de la machine, et presque tous les langages courants lui empruntent leur syntaxe.

Origine

Le C date des années 1970. Il a été créé par Dennis Ritchie, aux laboratoires Bell, pour écrire le système Unix. Il succède au langage B, d'où son nom. Linux, le noyau libre écrit à partir de 1991, est lui aussi écrit en C.

Remarque Unix et le langage B À vérifier

Les notes disent qu'« Unix était écrit en langage B ». La première version d'Unix (1969, Ken Thompson) était en fait écrite en assembleur ; B, conçu par Thompson, a servi d'ébauche, puis Ritchie en a tiré le C, dans lequel le noyau d'Unix a été réécrit en 1973. C'est sans doute ce que disait le cours : le C est né de B pour réécrire Unix.

Un langage impératif et typé

Le C est un langage impératif : un programme est une suite d'ordres qui modifient l'état de la mémoire. Il est aussi typé : chaque variable a un type, fixé à sa déclaration et vérifié à la compilation. Les notes en donnent la raison : avec un langage non typé, il est difficile de comprendre après coup ce qui s'est passé pendant l'exécution, car rien ne dit ce qu'une variable était censée contenir.

Complément « Très typé », vraiment ?

Les notes disent « très typé ». Il faut nuancer : le C est typé statiquement (les types sont connus à la compilation), mais il convertit volontiers d'un type à l'autre sans rien dire. int n = 3.9; compile et donne 3 ; un caractère est un petit entier, sur lequel on fait des additions. On dit souvent que le C est statiquement mais faiblement typé, à la différence de Java ou d'OCaml.

Le C est enfin la source de beaucoup d'autres langages pour la syntaxe : accolades, point-virgule, for (i = 0; i < n; i++), opérateurs ==, &&, ++ se retrouvent en C++, Java, C#, JavaScript ou PHP.

Les normes

Les notes indiquent que le C respecte la norme « Kernighan et Ritchie 78 ». Il s'agit du livre The C Programming Language de Brian Kernighan et Dennis Ritchie (1978), qui a longtemps tenu lieu de norme : on parle du « C K&R ».

Complément Les normes officielles

Le C a ensuite été normalisé : ANSI C en 1989 (C89, reprise par l'ISO en 1990 sous le nom C90), puis C99, C11, C17 et C23. C'est la norme ANSI qui a apporté const (voir plus bas) et les prototypes de fonctions. Avec gcc, on choisit la norme par une option : gcc -std=c99 -Wall prog.c -o prog. L'option -Wall, qui active les avertissements, devrait être systématique.

Langage généraliste et DSL

Les notes définissent les DSL (domain specific languages) : des langages créés pour un domaine particulier. Ajout SQL pour les bases de données, HTML pour les pages web ou les Makefile en sont des exemples. Le C, au contraire, est un langage généraliste : il sert à écrire n'importe quel programme, du système d'exploitation au jeu vidéo.

Complément De la source à l'exécutable

Un programme C passe par trois étapes, que gcc enchaîne d'un seul appel : le préprocesseur traite les lignes qui commencent par # (inclusions, constantes) ; le compilateur traduit le résultat en code machine ; l'éditeur de liens (linker) y joint les fonctions de bibliothèque comme printf.

$ gcc -Wall bonjour.c -o bonjour
$ ./bonjour
Bonjour !
#include <stdio.h>

int main(void)
{
    printf("Bonjour !\n");
    return 0;
}

Expressions et instructions notes, début et milieu

Un programme C est fait d'instructions, elles-mêmes construites à partir d'expressions. La différence entre les deux explique des écritures propres au C, comme a = b = 1.

Définition Expression, instruction

Une expression est une écriture qui a une valeur : 3, x + 1, a > b, mais aussi x = 5, dont la valeur est 5.

Une instruction est un ordre exécuté par le programme. La plus simple est une expression suivie d'un point-virgule : x = 5;, printf("ok");.

Remarque Ce que disent les notes À vérifier

Les notes écrivent : « Instruction : renvoie une valeur avec un point-virgule ». C'est l'inverse : c'est l'expression qui a une valeur ; le point-virgule en fait une instruction, et la valeur est alors abandonnée. Dans x = 5;, l'expression x = 5 vaut 5, mais personne ne récupère ce 5 : seul compte l'effet, ranger 5 dans x.

L'affectation est une expression

L'opérateur d'affectation = s'évalue de droite à gauche. Dans a = b = 1;, on range d'abord 1 dans b ; l'expression b = 1 vaut 1, valeur que l'on range ensuite dans a.

Complément Pourquoi c'est utile

Comme une affectation a une valeur, on peut l'utiliser dans une condition. C'est la forme de la boucle de lecture que l'on écrira plus bas : while ((c = getchar()) != EOF) lit un caractère, le range dans c, puis compare la valeur rangée à EOF. Les parenthèses autour de c = getchar() sont indispensables : != est prioritaire sur =.

Attention = n'est pas == Ajout

if (x = 0) range 0 dans x et vaut 0, donc faux : le bloc n'est jamais exécuté, et x est écrasé. La comparaison s'écrit if (x == 0). Avec -Wall, gcc signale l'erreur.

L'opérateur conditionnel

L'expression condition ? valeur_si_vrai : valeur_si_faux choisit entre deux valeurs. Les notes donnent l'exemple du maximum :

max = a > b ? a : b;   /* max reçoit a si a > b, b sinon */

Ajout C'est une expression, pas une instruction : elle a une valeur et peut se placer dans un calcul ou un appel, par exemple printf("%d\n", a > b ? a : b);.

Complément Les opérateurs courants

Les notes ne citent que l'affectation et l'opérateur conditionnel. Voici les autres, dont on se sert dès le premier TP.

Attention La division entière Ajout

Entre deux entiers, / donne le quotient entier : 7 / 2 vaut 3, et 7 / 2 * 1.0 vaut 3.0, car la division est faite avant la multiplication. Pour obtenir 3.5, il faut qu'un des opérandes soit flottant : 7.0 / 2 ou (double) 7 / 2. Depuis C99, le quotient est arrondi vers zéro : -7 / 2 vaut −3 et -7 % 2 vaut −1.

Ajout En C, il n'y a pas de type booléen de base (il n'existe que depuis C99, dans <stdbool.h>) : une condition est un entier, fausse si elle vaut 0 et vraie sinon. Une comparaison vaut 1 ou 0. Les opérateurs && et || n'évaluent leur second opérande que si c'est nécessaire.

Types, littéraux et identificateurs notes, milieu

Toute valeur écrite dans un programme, un littéral, a un type, que le compilateur déduit de son écriture. Les notes s'attardent sur les entiers et les caractères.

Complément Les types de base

Les tailles ne sont pas fixées par la norme, seulement des minimums ; celles du tableau sont celles d'un PC actuel (Linux 64 bits, obtenues avec sizeof). Chaque type entier existe aussi en version unsigned, sans signe.

Les entiers et leur base

La base d'un littéral entier se lit à son premier caractère :

  • s'il commence par un chiffre de 1 à 9, il est en base 10 : 255 ;
  • s'il commence par 0, il est en base 8 (octal) : 0377 ;
  • s'il commence par 0x, il est en base 16 (hexadécimal) : 0xFF.

Ces trois littéraux désignent la même valeur, 255.

Attention Le zéro qui change tout Ajout

printf("%d", 010); affiche 8, et non 10. Aligner des nombres en les complétant par des zéros à gauche (007, 010) change donc leur valeur. 09 est même une erreur de compilation : 9 n'est pas un chiffre octal.

Les caractères

Un caractère s'écrit entre apostrophes : 'A'. Sa valeur est son code dans la table ASCII, que le C utilise : 'A' vaut 65, 'a' vaut 97, '0' vaut 48.

Certains caractères ne s'impriment pas. On les écrit avec une barre oblique inverse : '\n' (passage à la ligne), '\t' (tabulation), et d'autres. De même pour les caractères qui ont un sens dans la syntaxe : l'apostrophe s'écrit '\'', les guillemets '\"'. Ces séquences d'échappement correspondent à une seule valeur dans la table ASCII, même si on les écrit avec deux caractères.

Complément Calculer avec des caractères

Comme un caractère est un nombre, on peut calculer avec. Les lettres et les chiffres se suivent dans la table ASCII, d'où deux formules que l'on retrouve dans les TD :

int chiffre = c - '0';           /* '7' - '0' vaut 7 */
char majuscule = c - 'a' + 'A';  /* 'a' devient 'A' si c est une minuscule */
int est_minuscule = c >= 'a' && c <= 'z';

La première sert à convertir un nombre lu caractère par caractère : nombre = nombre * 10 + c - '0'; (TD 3, exercice 6). La barre oblique inverse elle-même s'écrit '\\', et le caractère nul '\0' vaut 0.

Les chaînes de caractères

Une chaîne s'écrit entre guillemets : "abc". Une chaîne de \(n\) lettres occupe \(n + 1\) octets en mémoire : le dernier, le \((n+1)\)e, est le caractère nul '\0', qui marque la fin.

printf("%zu\n", sizeof("abc"));   /* 4 : a, b, c et '\0' */
printf("%zu\n", strlen("abc"));   /* 3 : strlen ne compte pas '\0' */

Attention 'a' n'est pas "a" Ajout

'a' est un caractère : un nombre, 97. "a" est une chaîne de deux octets, 'a' puis '\0', que le programme manipule par son adresse. Comparer un caractère à une chaîne, comme c[i] != "\0", compare un nombre à une adresse : la condition est toujours vraie. On écrit c[i] != '\0'.

Les identificateurs

Les noms des variables, des constantes et des fonctions sont des identificateurs. Les notes précisent que le caractère _ compte comme une lettre : il peut figurer dans un identificateur, et même le commencer.

Complément Les règles

Un identificateur est fait de lettres non accentuées, de chiffres et de _, et ne commence pas par un chiffre : nb_lignes et _tmp sont valides, 2x et état ne le sont pas. Majuscules et minuscules sont distinguées (Max et max sont deux noms). Les mots-clés du langage (int, while, return…) sont réservés. Par convention, les constantes s'écrivent en majuscules.

Nommer une constante notes, milieu

Écrire 3.14159 à dix endroits d'un programme est une source d'erreurs : on donne un nom à la valeur. Les notes listent trois façons de le faire.

La directive #define

Tout ce qui commence par # est une directive du préprocesseur, lue avant la compilation. Le préprocesseur fait un traitement purement textuel : après #define PI 3.14159, il remplace chaque PI du programme par le texte 3.14159, sans rien savoir du C.

Si l'on écrit #define PI 3.14159;, le point-virgule fait partie du texte remplacé, et le compilateur signale une erreur dès qu'on calcule avec cette constante.

Exemple Le point-virgule de trop Ajout

#define PI 3.14159;

double perimetre = 2 * PI * r;
/* devient, après le préprocesseur :
   double perimetre = 2 * 3.14159; * r;
   « * r; » seul n'a pas de sens : erreur de compilation */

Le message d'erreur porte sur la ligne qui utilise PI, pas sur le #define, ce qui le rend difficile à comprendre.

Attention Des parenthèses partout Ajout

Le remplacement textuel ignore les priorités. Avec #define CARRE(x) x * x, CARRE(1 + 2) devient 1 + 2 * 1 + 2, qui vaut 5 et non 9. On écrit #define CARRE(x) ((x) * (x)).

Les énumérations

Les notes disent que enum « sert à faire des listes ». Ajout Plus précisément, une énumération nomme une liste de constantes entières, numérotées à partir de 0, sauf valeur imposée :

enum couleur { ROUGE, VERT, BLEU = 10, JAUNE };
/* ROUGE vaut 0, VERT 1, BLEU 10, JAUNE 11 */

enum couleur c = VERT;

Ajout Le TP noté de la fourmi de Langton (TP/TP3 éval/) s'en sert pour les directions : typedef enum {sud, ouest, nord, est} t_direction;. Le typedef est présenté au cours 3.

Le qualificatif const

Depuis la norme ANSI, on peut aussi déclarer une variable dont la valeur ne peut plus changer : const double PI = 3.14159;. Ajout Contrairement à #define, cette constante a un type, vérifié par le compilateur, et toute tentative de la modifier est une erreur de compilation.

Lire et écrire un caractère notes, milieu

Les deux fonctions d'entrée-sortie les plus simples lisent ou écrivent un seul caractère. Elles suffisent pour les premiers TD, où l'on traite un texte lettre par lettre.

Définition getchar et putchar

getchar() lit un caractère sur l'entrée standard (le clavier, par défaut) et renvoie son code.

Ajout putchar(c) écrit le caractère c sur la sortie standard (l'écran). Les deux fonctions sont déclarées dans <stdio.h>. Les notes laissent la définition de putchar en blanc.

Complément La fin du fichier : EOF

Quand il n'y a plus rien à lire, getchar renvoie la constante EOF (end of file), qui vaut −1. Au clavier, on la provoque avec Ctrl+D sous Linux, Ctrl+Z puis Entrée sous Windows. C'est pourquoi le résultat de getchar se range dans un int, et non dans un char : il faut pouvoir représenter les 256 caractères et la valeur −1, qui ne se confond avec aucun. Le cours 2 y revient.

Exemple Recopier l'entrée (TD 3, exercice 1)

Le programme le plus court qui utilise ces deux fonctions recopie son entrée sur sa sortie, caractère par caractère, jusqu'à la fin :

#include <stdio.h>

int main(void)
{
    int c;
    while ((c = getchar()) != EOF)
        putchar(c);
    return 0;
}
$ gcc -Wall copie.c -o copie
$ echo "Bonjour" | ./copie
Bonjour

Exemple Compter les lignes (TD 3, exercice 3)

#include <stdio.h>

int main(void)
{
    int c, nl = 0;
    while ((c = getchar()) != EOF)
        if (c == '\n')
            nl++;
    printf("%d lignes\n", nl);
    return 0;
}

Attention Deux erreurs vues dans les TD Ajout

Compteur non initialisé. Dans int c, nsp, ntab, nl = 0;, seul nl reçoit 0 : nsp et ntab contiennent n'importe quoi, et le programme affiche des nombres absurdes. Chaque variable s'initialise à part : int nsp = 0, ntab = 0, nl = 0;.

void main(). La norme impose int main(void) : la valeur renvoyée par main est le code de retour du programme, lu par le système (0 si tout va bien). Le cours 3 en parle.

Coder les nombres et les caractères notes, fin

La mémoire ne contient que des bits. La dernière partie du cours montre comment on y range un nombre à virgule, un chiffre décimal ou un caractère de n'importe quelle langue.

Les nombres flottants : la norme IEEE 754

Un float (« simple ») est codé sur 32 bits, un double sur 64 bits. Les 32 bits d'un float se découpent ainsi : 1 bit pour le signe, 8 bits pour l'exposant, 23 bits pour la mantisse.

La valeur se décode avec la formule des notes, où « 1,mantisse » désigne le nombre binaire formé d'un 1, de la virgule, puis des 23 bits de la mantisse :

\[ \text{nombre} = (-1)^{s} \times 1{,}m \times 2^{\,e - 127} \]

Ajout Les notes écrivent « signe × 1,mantisse × … » : le signe vaut +1 si le bit \(s\) est 0, −1 s'il est 1. Le 1 avant la virgule n'est pas stocké, puisqu'il est toujours là : c'est le bit caché. Le décalage de 127 permet de coder des exposants négatifs avec un champ sans signe.

Exemple Coder −6,5 Ajout

  1. Signe : le nombre est négatif, donc \(s = 1\).
  2. En binaire, \(6{,}5 = 110{,}1_2 = 1{,}101_2 \times 2^{2}\).
  3. Exposant stocké : \(e = 2 + 127 = 129 = 1000\,0001_2\).
  4. Mantisse : les bits après la virgule, 101, complétés par des zéros jusqu'à 23 bits.
  5. On assemble : 1 10000001 10100000000000000000000, soit C0D00000 en hexadécimal, ce que confirme un programme qui affiche les octets du float −6.5f.

Attention 0,1 n'existe pas en binaire Ajout

Comme 1/3 en décimal, 0,1 a une écriture binaire infinie : le float le plus proche vaut 0,1000000015, et en double, 0.1 + 0.2 == 0.3 est faux (la somme vaut 0,30000000000000004). On ne compare donc jamais deux flottants avec ==, mais leur écart : fabs(x - y) < 1e-9.

Complément Le double et les valeurs spéciales

Un double a 1 bit de signe, 11 bits d'exposant (décalage 1023) et 52 bits de mantisse, soit environ 16 chiffres décimaux significatifs contre 7 pour un float. Un exposant tout à 0 ou tout à 1 est réservé : zéro et les très petits nombres d'un côté, l'infini et NaN (not a number, résultat de 0.0/0.0) de l'autre.

Le BCD

Le BCD (binary coded decimal, décimal codé en binaire) code chaque chiffre décimal sur 4 bits. Ce codage sert à commander des afficheurs 7 segments. Ajout Par exemple, 59 se code 0101 1001 : un groupe de 4 bits par chiffre, alors qu'en binaire pur 59 s'écrit 0011 1011. Le BCD gaspille de la place (les combinaisons 1010 à 1111 ne servent pas) mais évite toute conversion pour afficher.

Les caractères : ASCII, Unicode et UTF-8

Ajout La table ASCII code 128 caractères sur 7 bits : lettres non accentuées, chiffres, ponctuation et caractères de contrôle. C'est trop peu pour le français, et à plus forte raison pour les autres écritures.

La norme Unicode, ou ISO/CEI 10646, recense tous les caractères (les glyphes) inventés par l'humanité et attribue un numéro à chacun. Pour des raisons de compatibilité, elle a repris la table ASCII au début (numéros 0 à 127), puis la table ISO 8859-1, dite Latin-1 (numéros 128 à 255, où figurent é, è, à, ç…).

Reste à ranger ces numéros en mémoire. UTF-8 (Unicode Transformation Format) est un codage de longueur variable. Les notes le décrivent par une image de train : une locomotive seule commence toujours par un 0 ; une locomotive suivie de wagons commence par une série de 1 suivie d'un 0.

Complément Locomotives et wagons

Le nombre de 1 en tête de la locomotive donne le nombre total d'octets du caractère ; chaque wagon commence par 10. Les bits notés x portent le numéro Unicode.

Exemple Coder « é » en UTF-8 Ajout

  1. « é » porte le numéro U+00E9, soit 233, en binaire 1110 1001.
  2. 233 est entre 128 et 2 047 : il faut deux octets, soit 11 bits utiles. On écrit 233 sur 11 bits : 000 1110 1001.
  3. Les 5 premiers bits vont dans la locomotive, 110 00011 ; les 6 derniers dans le wagon, 10 101001.
  4. Résultat : C3 A9. Un fichier source en UTF-8 contenant "é" donne bien ces deux octets, et strlen("é") vaut 2.

Remarque Pourquoi ce codage est malin Ajout

Un texte en ASCII est déjà un texte UTF-8 valide. Et comme un wagon commence toujours par 10, on retrouve le début d'un caractère en partant de n'importe quel octet. Le revers, en C : un char est un octet, pas un caractère. Les lettres accentuées occupent plusieurs char, et un programme qui compte les lettres d'un texte français en comptant les octets se trompe.

Exercices ajout

Les notes se terminent par « finir les exos sur la feuille », mais la feuille n'est pas sur le Drive. Les exercices suivants portent sur les mêmes notions ; les solutions sont proposées, pas celles de l'enseignant.

Exercice 1 Littéraux

Que vaut chacune des expressions suivantes : 017, 0x2A, 'B' - 'A', '5' - '0', sizeof("C\n") ?

Solution proposée

15 (octal : \(8 + 7\)) ; 42 (\(2 \times 16 + 10\)) ; 1 ; 5 ; 3 ('C', '\n', qui compte pour un seul caractère, et '\0').

Exercice 2 Décoder un float

Quelle valeur représente le float 41 20 00 00 (en hexadécimal) ?

Indice

Écrire les 32 bits, puis séparer 1, 8 et 23 bits.

Solution proposée

En binaire : 0 10000010 01000000000000000000000. Signe 0, donc positif ; exposant \(130 - 127 = 3\) ; mantisse \(1{,}01_2 = 1{,}25\). Valeur : \(1{,}25 \times 2^3 = 10\).

Exercice 3 UTF-8

Le symbole de l'euro, €, porte le numéro U+20AC. Combien d'octets occupe-t-il en UTF-8, et lesquels ?

Solution proposée

0x20AC vaut 8 364, entre 2 048 et 65 535 : trois octets. Sur 16 bits : 0010 000010 101100. Locomotive 1110 0010, wagons 10 000010 et 10 101100 : E2 82 AC.

Exercice 4 En majuscules

Écrire un programme qui recopie son entrée en remplaçant chaque minuscule non accentuée par la majuscule correspondante, sans utiliser toupper.

Indice

Partir de la boucle de recopie et transformer c avant putchar quand il est entre 'a' et 'z'.

Solution proposée 
#include <stdio.h>

int main(void)
{
    int c;
    while ((c = getchar()) != EOF) {
        if (c >= 'a' && c <= 'z')
            c = c - 'a' + 'A';
        putchar(c);
    }
    return 0;
}

La version du TD 3 (exercice 5) teste (c = getchar()) + 'A' - 'a' != EOF et écrit putchar(c) dans les deux branches : la boucle ne s'arrête plus au bon moment et rien n'est converti. Il vaut mieux tester EOF seul et convertir dans le corps.

À retenir

L'essentiel

  • Le C (Dennis Ritchie, années 1970) est impératif, compilé, statiquement typé ; sa syntaxe a inspiré C++, Java, JavaScript…
  • Une expression a une valeur ; suivie d'un ;, elle devient une instruction et sa valeur est perdue. L'affectation est une expression, évaluée de droite à gauche.
  • Un littéral entier qui commence par 0 est en octal, par 0x en hexadécimal.
  • Un caractère est un petit entier (son code ASCII) ; '\n' est un seul caractère. Une chaîne de \(n\) lettres occupe \(n+1\) octets, le dernier étant '\0'.
  • #define fait un remplacement textuel avant la compilation : ni point-virgule, et des parenthèses autour des expressions.
  • enum nomme des constantes entières, const déclare une variable non modifiable et typée.
  • getchar renvoie un int, qui vaut EOF en fin de flux ; la boucle while ((c = getchar()) != EOF) traite toute l'entrée.
  • Un float : 1 bit de signe, 8 d'exposant, 23 de mantisse ; valeur \((-1)^s \times 1{,}m \times 2^{e-127}\). On ne compare pas deux flottants avec ==.
  • UTF-8 code chaque caractère Unicode sur 1 à 4 octets : la locomotive annonce le nombre d'octets par ses 1 de tête, chaque wagon commence par 10.

Auto-évaluation

Que vaut l'expression x = 5, et que devient cette valeur dans l'instruction x = 5; ?

Elle vaut 5. Dans l'instruction, cette valeur est abandonnée : seul compte l'effet de bord, ranger 5 dans x.

Pourquoi printf("%d", 012) affiche-t-il 10 ?

Le zéro de tête fait lire 012 en base 8 : \(1 \times 8 + 2 = 10\).

Combien d'octets occupe "Bonjour" en mémoire ?

Huit : les sept lettres et le caractère nul final '\0'.

Avec #define N 10;, pourquoi int t[N]; ne compile-t-il pas ?

Le préprocesseur remplace N par le texte 10; : on obtient int t[10;];, qui n'a pas de sens.

Pourquoi ranger le résultat de getchar() dans un int plutôt que dans un char ?

Pour pouvoir distinguer EOF (−1) de tous les caractères possibles : un char ne peut pas représenter les 256 valeurs d'octet plus une 257e.

Que vaut le float dont les bits sont 0 01111111 000…0 ?

Exposant \(127 - 127 = 0\), mantisse \(1{,}0\) : la valeur est \(1\).

En UTF-8, que dit l'octet 1110xxxx ?

C'est une locomotive suivie de deux wagons : le caractère occupe trois octets.
