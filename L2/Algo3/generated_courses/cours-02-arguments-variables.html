Fonctions à nombre variable d'arguments

printf accepte un, deux ou dix arguments. Ce chapitre montre comment écrire soi-même une telle fonction en C, par trois méthodes : à la manière de argc et argv, en lisant les arguments dans la pile avec <stdarg.h>, et à la manière de printf, avec une chaîne de format.

Objectifs

  • Écrire le prototype d'une fonction à nombre variable d'arguments.
  • Parcourir les arguments en surnombre avec va_list, va_start, va_arg et va_end.
  • Choisir entre nombre d'arguments, sentinelle et chaîne de format, et connaître les promotions de types.

Prérequis

  • Cours 1 : pointeurs, tableaux de chaînes.
  • Les paramètres argc et argv de main.

Le problème p. 1

La fonction printf prend un nombre variable d'arguments :

printf( "coucou\n" ) ;                       /* 1 argument */
printf( "x=%d\n" , x ) ;                     /* 2 arguments */
printf( "nom=%s prenom=%s score=%d\n"
        , nom , prenom , score ) ;           /* 4 arguments */

Programmer une telle fonction pose deux problèmes.

  1. Faire accepter les appels par le compilateur. En C, une fonction a un nombre fixe de paramètres : le compilateur vérifie que le nombre de paramètres effectifs (ceux que l'on passe à l'appel) est égal au nombre de paramètres formels (ceux du prototype). Solution : une extension de la définition des prototypes, la section suivante.
  2. Transmettre correctement les arguments. Il existe plusieurs méthodes, plus ou moins simples et portables : argc/argv, la pile, la méthode de printf.

Le prototype avec points de suspension p. 2

La norme du C autorise une fonction dont la fin de la liste d'arguments est inconnue.

Définition Prototype variadique

La liste inconnue d'arguments s'écrit à la fin du prototype : une virgule, puis trois points de suspension , .... Elle doit suivre au moins un paramètre nommé.

void f1( int x, int y , ... )   /* OK */
{
}

void f2( char * format , ... )   /* OK */
{
}

/* error: syntax error before ',' token */
void f3( ,... ) /* KO */
{

}

Les points de suspension disent au compilateur de ne pas s'occuper du nom, du nombre ni du type des arguments en surnombre. Le compilateur gère les arguments correspondant aux paramètres formels ; les arguments en surnombre, c'est le programmeur qui les gère.

Note Depuis C23 Hors programme

La norme C23 accepte void f( ... ), sans paramètre nommé. Le cours suit les normes précédentes, où au moins un paramètre formel est obligatoire, et c'est ce qu'attend gcc par défaut.

La méthode argc, argv p. 2

La première méthode n'utilise pas les points de suspension : elle imite le passage des arguments de main. On passe un nombre d'arguments et un tableau de chaînes.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAXARG 10

void f( int argc , char * argv[]  )
{
  int i ;

  for( i=0 ; i<argc ; i++ )
    {
      printf( "\tfoncton f : argv[%d] = %s\n" , i , argv[i] ) ;
    }
  return ;
}

int main( int argc , char * argv[] )
{
  int f_argc ;
  char * f_argv[MAXARG] ;
  int i ;

  /* Construction des parametres */
  f_argc = 3 ;
  f_argv[0] = malloc( sizeof(char) * strlen("azertyuiop")+1 ) ;
  strcpy( f_argv[0] , "azertyuiop" ) ;
  f_argv[1] = malloc( sizeof(char) * strlen("123")+1 ) ;
  strcpy( f_argv[1] , "123" ) ;
  f_argv[2] = malloc( sizeof(char) * strlen("45.67")+1 ) ;
  strcpy( f_argv[2] , "45.67" ) ;

  /* Appel de la fonction avec nombre variable de parametres */
  printf(" 1er appel de f avec 3 arguments\n");
  f( f_argc , f_argv ) ;

  for( i=0 ; i<3 ; i++ )
    free( f_argv[i] ) ;

 /* Construction des parametres */
  f_argc = 2 ;
  f_argv[0] = malloc( sizeof(char)*strlen("WWW")+1 );
  strcpy( f_argv[0] , "WWW" );
  f_argv[1] = malloc( sizeof(char)*strlen("XXXXXXX")+1 );
  strcpy( f_argv[1] , "XXXXXXX" );

 /* Appel de la fonction avec nombre variable de parametres */
  printf(" 1er appel de f avec 2 arguments\n");
  f( f_argc , f_argv ) ;

  for( i=0 ; i<2 ; i++ )
    free(f_argv[i]) ;

  return(0) ;
}

Avantage

  • Totalement portable : c'est du C ordinaire.

Inconvénient

  • L'écriture du passage des paramètres est « un peu » lourde : il faut construire le tableau avant chaque appel, et tout passer sous forme de chaînes.

La méthode de la pile p. 3

La deuxième méthode utilise le prototype , ... et va chercher les arguments en surnombre dans la pile d'exécution, où l'appelant les a déposés. Les outils sont dans <stdarg.h>.

Méthode Parcourir les arguments en surnombre

  1. Déclarer une variable va_list ap ;, qui pointera successivement sur chacun des arguments en surnombre.
  2. va_start( ap , dernier ) ; : initialiser ap sur le premier argument en surnombre ; dernier est le nom du dernier paramètre formel.
  3. va_arg( ap , type ) : renvoyer l'argument courant, lu avec le type indiqué, et passer au suivant.
  4. va_end( ap ) ; : terminer proprement, comme l'exige la norme.

La fonction doit savoir combien d'arguments lire. Le programme methode_pile.c montre les deux variantes : passer le nombre en paramètre formel, ou terminer la liste par une sentinelle, ici NULL.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include <stdarg.h>	/* Utilisation :
			 *  - du type va_list
			 *  - des fonctions va_start, va_arg, va_end
			 */

/* Variante avec le nombre d'arguments */
void f_nb( int x , int y , int nb_arg , ...  )
{
  int i = 0 ;
  /* ap est une va_list qui pointera successivement sur chacun des arguments en surnombre */
  va_list ap ;

  printf( "Arguments formels\n" )  ;
  printf( "\tx = %d\n" , x ) ;
  printf( "\ty = %d\n" , y ) ;
  printf( "\tnb_arg = %d\n" , nb_arg ) ;

  /* on initialise ap pour qu'il pointe sur le 1er argument en surnombre  */
  va_start( ap , nb_arg ) ;

  printf("Arguments en surnombre\n") ;
  for( i=0 ; i<nb_arg ; i++ )
    {
      /*
       * a chaque appel va_arg renvoie un argument
       * il faut  lui preciser le type de cet argument attendu
       * Ici tous les arguments sont du meme type : des chaines de caracteres
       */
      printf( "\t numero %d = %s\n" , i , va_arg( ap , char * ) ) ;
    }

  /* Pour terminer proprement, d'apres la norme */
  va_end(ap) ;

  return ;
}

/* Variante sans le nombre d'arguments */
void f_sentinelle( int x , int y , ...  )
{
  int i = 0 ;
  char * arg ;
  va_list ap ;

  printf( "Arguments formels\n" )  ;
  printf( "\tx = %d\n" , x ) ;
  printf( "\ty = %d\n" , y ) ;

  /* on initialise ap pour qu'il pointe sur le 1er argument en surnombre  */
  va_start( ap , y ) ;
  arg = va_arg( ap , char * ) ;

  printf("Arguments en surnombre\n") ;
  while( arg != NULL )
    {
      printf( "\t numero %d = %s\n" , i ,  arg ) ;
      i++ ;
      arg = va_arg( ap , char * );
    }

  va_end(ap) ;

  return ;
}

int main( int argc , char * argv[] )
{
  int bidon1 = 99 ;
  int bidon2 = 88 ;

  /* Appel de la fonction en indiquant le nombre de parametres */
  printf("\n\n1er appel de f en precisant le nombre  d'arguments\n");
  f_nb( bidon1 , bidon2 , 5 , "aaaaa" , "bbbb" , "ccc" , "dd" , "e" ) ;

  /* Appel de la fonction avec sentinelle NULL apres les parametres */
  printf("\n\n2ieme appel de f sans le nombre d'arguments\n");
  f_sentinelle( bidon1 , bidon2 , "aaaaa" , "bbbb" , "ccc" , "dd" , "e" , NULL ) ;

  return(0) ;
}

Les promotions de types

Les arguments en surnombre n'ont pas de type déclaré : le compilateur les convertit selon des règles anciennes, héritées du C d'avant les prototypes. Il faut lire chaque argument avec va_arg sous son type après conversion.

Type originalType après conversion
int et shortint
unsigned charunsigned int
unsigned shortunsigned int
floatdouble
tableau de type_tpointeur sur type_t

Attention Ce que dit la norme À vérifier

La norme parle de promotions des arguments par défaut (default argument promotions) : char, short et leurs versions unsigned deviennent int quand int peut représenter toutes leurs valeurs, ce qui est le cas sur les machines courantes ; unsigned int sinon. Le tableau du polycopié, qui envoie unsigned char et unsigned short vers unsigned int, ne correspond donc pas aux compilateurs actuels, et il oublie char (promu en int). En pratique : va_arg( ap , int ) pour tout entier plus petit qu'un int, va_arg( ap , double ) pour un float.

Quand les arguments en surnombre sont de types différents, la fonction doit connaître l'ordre dans lequel ils arrivent :

void f( int x , int y , ...  )
{
  va_list ap ;
  /* … affichage de x et y … */
  va_start( ap , y ) ;

  printf("Arguments en surnombre\n") ;
  /* Le 1er doit etre un int */
  printf( "\t1er (int) = %d\n" , va_arg( ap , int ) );
  /*
   * Le 2ieme un float MAIS
   * float est promu en double quand c'est passe par ...
   * si pas traite comme un double alors plantage
   */
  printf( "\t2ieme (float) = %G\n" , va_arg( ap , double ) ) ; /* OK */
  /*   printf( "\t2ieme (float) = %G\n" , va_arg( ap , float ) ) ; /\* KO *\/ */
  /* Le 3ieme un double */
  printf( "\t3ieme (double) = %G\n" , va_arg( ap , double ) ) ;
  /* Le 4ieme un char * */
  printf( "\t4ieme (char *) = %s\n" , va_arg( ap , char * ) ) ;

  va_end(ap) ;
}
/* appel */
f( bidon1 , bidon2 , 12 , 34.56 , 12E-10 , "azertyuiop" , NULL ) ;

Lire un float par va_arg( ap , float ) est une erreur : l'argument a été transmis comme un double. gcc avertit d'ailleurs que le programme s'arrêtera s'il passe par là ('float' is promoted to 'double' when passed through '...').

Avantage

  • L'appel s'écrit simplement, avec des arguments de tout type, sans construire de tableau.

Inconvénients

  • Pas totalement portable, mais la partie non portable se réduit au fichier <stdarg.h>.
  • La variante à sentinelle est dangereuse si l'appelant « oublie » le NULL final : la fonction lit au-delà des arguments.
  • Il faut tenir compte des promotions de types.
  • Avec des arguments hétérogènes, la fonction doit connaître leur ordre d'arrivée, sinon les erreurs sont probables.
  • Il faut au moins un argument formel, nécessaire à va_start.

Complément Portabilité et sentinelle

  • <stdarg.h> fait partie de la norme depuis C89 : le code qui l'utilise est portable. Ce qui ne l'est pas, c'est la façon dont les macros sont réalisées (sur x86-64, les premiers arguments passent par des registres et non par la pile), et c'est justement ce que l'en-tête cache.
  • NULL peut être défini comme l'entier 0. Passé dans ..., il n'est alors pas converti en pointeur, et lire un char * à sa place est faux là où un int et un pointeur n'ont pas la même taille. La sentinelle sûre est (char *)NULL, comme pour execl.
  • gcc vérifie la sentinelle si l'on déclare void f_sentinelle( int x , int y , ... ) __attribute__((sentinel)) ; : un appel sans NULL final provoque un avertissement.

La méthode printf p. 4

La troisième méthode fait comme printf : le premier argument, une chaîne de format, décrit le nombre et le type des arguments qui suivent. Les arguments peuvent alors être hétérogènes, dans n'importe quel ordre.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include <stdarg.h>

void f( char * format, ...  )
{
  va_list ap ;
  int i = 0 ;
  int nb_arg = 0 ;

  printf( "Arguments formels\n" )  ;
  printf( "\tformat = %s\n" , format ) ;

  va_start( ap , format ) ;

  printf("Arguments en surnombre\n") ;
  nb_arg = strlen(format) ;
  for(i=0 ; i<nb_arg ; i++)
    {
      printf("\t numero %d " , i );
      switch(format[i])
	{
	case 'd' :  /* C'est un int */
	  printf( "(int) = %d\n" , va_arg( ap , int ) );
	  break ;
	case 'f' : /* C'est un float mais il a ete converti en double */
	  printf( "(float) = %G\n" , va_arg( ap , double ) ) ;
	  break ;
	case 'D' : /* C'est un double */
	  printf( "(double) = %G\n" , va_arg( ap , double ) ) ;
	  break ;
	case 's' : /* C'est un char * */
	  printf( "(char *) = %s\n" , va_arg( ap , char * ) ) ;
	  break ;
	default :
	  printf( "format inconnu\n" );
	  break ;
	}
    }
  va_end(ap) ;

  return ;
}

int main( int argc , char * argv[] )
{

  /* Appel de la fonction avec nombre variable de parametres */

  printf("\n\nAppel de f_nb( \"dfDs\" , 12 , 34.56 , 12E-10 , \"azertyuiop\" , NULL ) \n") ;
  f( "dfDs" , 12 , 34.56 , 12E-10 , "azertyuiop" ) ;

  printf( "\n\nAppel de   f( \"sds\" , \"coucou\" , 99 , \"bonjour\" ) ; \n") ;
  f( "sds" , "coucou" , 99 , "bonjour" ) ;

  return(0) ;
}

Avantage

  • Des arguments hétérogènes, dans n'importe quel ordre : le format dit à la fonction ce qu'elle doit lire.

Inconvénient

  • Elle repose sur la méthode de la pile : elle n'est donc pas totalement portable non plus.

Attention Le format fait foi Ajout

Si le format ne correspond pas aux arguments (un d pour une chaîne, ou plus de lettres que d'arguments), va_arg lit n'importe quoi : comportement indéfini. Pour printf elle-même, gcc compare format et arguments (-Wformat, inclus dans -Wall) ; pour sa propre fonction, l'attribut __attribute__((format(printf, 1, 2))) n'aide que si le format suit les conventions de printf.

Exercice La somme de n entiers Ajout

Écrire une fonction int somme( int n , ... ) qui renvoie la somme des n entiers qui suivent : somme( 3 , 10 , 20 , 30 ) vaut 60, et somme( 0 ) vaut 0.

Indice

C'est la variante « avec le nombre d'arguments » de la méthode de la pile ; le dernier paramètre formel est n.

Solution proposée 
#include <stdio.h>
#include <stdarg.h>

int somme( int n , ... )
{
  va_list ap ;
  int s = 0 ;
  va_start( ap , n ) ;
  for( int i = 0 ; i < n ; i++ )
    s += va_arg( ap , int ) ;
  va_end( ap ) ;
  return s ;
}

int main()
{
  printf( "%d %d\n" , somme( 3 , 10 , 20 , 30 ) , somme( 0 ) ) ;
  return 0 ;
}
$ ./somme
60 0

Un appel somme( 2 , 1.5 , 2.5 ) compilerait sans erreur mais donnerait n'importe quoi : les arguments sont des double, lus comme des int.

À retenir

L'essentiel

  • Le prototype d'une fonction variadique finit par , ..., après au moins un paramètre formel : void f( char * format , ... ).
  • Le compilateur ne vérifie ni le nombre ni le type des arguments en surnombre : c'est au programmeur de les gérer.
  • Méthode argc/argv : un nombre et un tableau de chaînes ; portable, mais lourde à l'appel.
  • Méthode de la pile (<stdarg.h>) : va_list ap, va_start(ap, dernier_formel), va_arg(ap, type) pour chaque argument, va_end(ap).
  • La fonction doit savoir où s'arrêter : un nombre passé en paramètre, ou une sentinelle (NULL) que l'appelant ne doit pas oublier.
  • Promotions : un float arrive en double, un char ou un short en int ; va_arg(ap, float) est une erreur.
  • Méthode printf : une chaîne de format décrit le type et l'ordre des arguments, qui peuvent être hétérogènes.

Auto-évaluation

Pourquoi void f3( , ... ) ne compile-t-il pas ?

La liste variable doit suivre au moins un paramètre formel ; va_start en a besoin pour situer le premier argument en surnombre.

Quel est le second argument de va_start ?

Le nom du dernier paramètre formel de la fonction, celui qui précède les ....

On passe 3.5f dans les .... Comment le lire ?

va_arg( ap , double ) : un float est promu en double quand il passe par les points de suspension.

Quel est le risque de la méthode avec sentinelle ?

Si l'appelant oublie le NULL final, la fonction continue de lire au-delà des arguments réels : comportement indéfini, plantage probable.

Quel avantage la méthode printf a-t-elle sur la méthode de la pile simple ?

La chaîne de format indique le type de chaque argument : ils peuvent être hétérogènes et dans n'importe quel ordre.

Quelle méthode est totalement portable, et pourquoi n'est-elle pas toujours choisie ?

La méthode argc/argv, qui n'utilise que du C ordinaire ; mais il faut construire un tableau de chaînes avant chaque appel, ce qui est lourd.
