Découverte rapide de l'environnement Postgre p. 1–2

Cette partie découverte ne doit pas vous prendre plus de 30 minutes (quasi tout est dans une diapo du cours !). Au bout de 30 minutes : vous devez obligatoirement passer à la partie suivante du TP.

Un utilisateur PostgreSQL a été créé sur le serveur PostgreSQL du département info pour chaque étudiant de L2. Ce serveur PostgreSQL est hébergé sur le serveur UNIX (host) nommé erebor. Par exemple, l'étudiante se nommant Nathalie Camelin et portant le numéro s2401007 aura le compte suivant : login etu_s2401007 (etu_numéro étudiant), mot de passe CaNa (2 premières lettres du nom + 2 premières lettres du prénom). Pour ceux ayant un nom composé, demandez à votre enseignant votre mot de passe.

Découvrons comment interroger le SGBD depuis UNIX :

  1. Dans l'environnement UNIX et grâce à la commande psql, listez les différentes bases de données gérées par le serveur PostgreSQL du département info.

Comme indiqué en cours, vous devez ouvrir un terminal et utiliser la commande psql, le client PostgreSQL. Il s'agit ici de lister les bases de données hébergées par le serveur, l'option à utiliser est donc -l (l pour listing) :

$ psql -U login -h host -l

Maintenant que nous connaissons toutes les bases existantes, nous pouvons tenter de nous connecter à l'une d'elles. Par exemple, dans toute la liste, j'ai bien vu qu'il existe une base qui se nomme booktown. Le grand saut, plongeons dans le monde merveilleux des SGBDR :

  1. Quittez maintenant l'environnement UNIX en vous connectant à la base de données booktown.

Comme indiqué en cours, pour se connecter à une base de données, il faut saisir la commande psql -U login -h host -d database. Par exemple, Nathalie devra saisir :

$ psql -U s2301007 -h erebor -d booktown

Bienvenue dans le monde merveilleux de Postgre ! Découvrons les commandes de base de PostgreSQL :

  1. Combien de tables contient booktown ?
  2. Quelle est la structure de la table auteurs ?
  3. Affichez la liste des commandes PostgreSQL.
  4. Affichez la liste des commandes SQL.
  5. Affichez l'aide pour la commande CREATE TABLE.
  6. Connectez-vous à votre base de données sans quitter l'environnement PostgreSQL.
  7. Indiquez la commande PostgreSQL qui permet d'exécuter des commandes Unix.

Base de données Entreprise p. 3–4

Pour ce TP, une base de données emp_num a été créée pour chaque étudiant. Pour travailler sur cette partie, vous devez être connecté dans votre base de données. Ne sortez pas de l'environnement UNIX, utilisez simplement la commande \c. Par exemple pour Nathalie : \c emp_s2301007.

Rappel du modèle

Modèle relationnel correspondant :

emp (id_emp, nom_emp, metier, #id_chef, date_emb, sal, comm, #id_dep)

dep (id_dep, nom_dep, loc)

grade (id_grade, min_sal, max_sal)

Attention, avant de créer la table des employés, téléchargez le fichier Script_Insert_Emp.txt (ici script.txt), qui contient les commandes d'insertion des employés. Si vous ne voulez pas modifier vos structures de tables, il faut prendre en compte l'ordre, le type de valeurs et la valeur des commandes insert.

  1. Créez la table des employés selon le schéma emp (id_emp, nom_emp, metier, #id_chef, date_emb, sal, comm, #id_dep) avec les contraintes suivantes : la clé primaire est id_emp ; id_dep est une clé étrangère sur la table dep ; le salaire et la commission doivent être des numériques flottants qui acceptent 2 chiffres après la virgule ; les seules valeurs acceptées par l'attribut metier seront Analyste, President, Manager, Secretaire, Vendeur.
  2. Une fois la table emp créée, vous pouvez maintenant la modifier afin d'indiquer que l'attribut id_chef est une clé étrangère sur l'attribut id_emp de la table emp.
  3. Insertion des données dans emp : insérez les enregistrements de Script_Insert_Emp.txt disponible sur UMTICE. Si vous avez des soucis d'insertion c'est que vous n'avez pas créé la structure de votre table correctement, supprimez-la et recréez-la en suivant bien le schéma.

Regardons le code SQL du script

  • L'insertion des employés n'a pas été faite dans n'importe quel ordre ! Les employés étant « chef » d'un autre employé sont toujours insérés AVANT tous leurs subordonnés. Sinon l'insertion des subordonnés ne serait pas possible en raison de la contrainte de clé étrangère sur id_chef.
  • Les valeurs de départements dans l'attribut id_dep de la table emp sont obtenues par une requête SELECT. Cela permet de ne pas avoir à gérer les identifiants de la table dep.

À vérifier L'affichage attendu de la question 21 montre SMITH, retiré de la base à la question 15 : il a sans doute été produit avant cette suppression.

Remarque importante

On se rend bien compte qu'il aurait été impossible d'ajouter la contrainte AVANT d'avoir modifié les valeurs de la colonne comm. En effet, si celle-ci n'accepte plus de valeur NULL, la présence d'un seul employé qui n'aurait pas de commission empêche de valider la contrainte… et donc il y a une erreur et donc la contrainte ne peut pas être acceptée par le SGBD. En revanche, s'il y a des valeurs partout, même si ce sont des 0, on peut mettre en place la contrainte.

Attention Ce qui change par rapport à la fac

  • Les commandes du client psql (\d, \c, \h…) ne sont pas du SQL : la console les refuse. La partie 1 se fait à la fac.
  • Le script fourni n'est inséré qu'une fois les tables créées : tant que les questions 1 à 6 sont vides, l'exécution s'arrête sur lui.
  • « Aujourd'hui » (question 12) est la date du jour où l'on exécute.

À retenir

Les méthodes

  • Les tables se créent dans l'ordre des références : grade et dep avant emp. La clé étrangère réflexive id_chef s'ajoute après coup, sur la table déjà créée.
  • Le script d'insertion impose l'ordre et le type des colonnes : on crée emp exactement selon le schéma.
  • Un chef est inséré avant ses subordonnés, sinon la clé étrangère sur id_chef refuse l'insertion.
  • Une contrainte NOT NULL ne s'ajoute qu'une fois les valeurs nulles remplacées.
  • Le compte rendu ne contient que les commandes, en texte brut ; chez soi, la console les rejoue toutes sur une base neuve.

Auto-évaluation

Pourquoi ajouter la clé étrangère id_chef après la création de emp ?

Elle référence la table elle-même : le sujet la fait ajouter une fois la table créée, pour découvrir la modification d'une structure existante.

Pourquoi KING est-il inséré le premier ?

Il n'a pas de chef, et il est le chef de JONES, BLAKE et CLARK : ses subordonnés ne peuvent être insérés qu'après lui.

Comment rendre une colonne obligatoire quand elle contient déjà des NULL ?

D'abord remplacer les NULL, puis ajouter la contrainte : dans l'autre ordre, le SGBD la refuse, puisque des lignes la violent déjà.

Les commandes \d et \c sont-elles du SQL ?

Non : ce sont des commandes du client psql, que le serveur ne reçoit pas.
